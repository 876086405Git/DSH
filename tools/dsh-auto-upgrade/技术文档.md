# DSH 全自动升级工具 · 完整技术文档

> 从初版到 v4.9 的全部问题、修复方案、注意事项与使用说明
>
> 文档版本：2026-11-13　工具版本：v4.9（本机适配版）

## 一、这个工具是干什么的

DSH（DeepSeek Harness）桌面端自带升级经常失败。这个工具用一条命令把「查版本 → 下载 → 校验 → 杀进程 → 备份 → 安装 → 核验 → 启动 → 健康检查 → 失败自动回滚」全部自动化。

**它解决的问题**（都是本机实测踩到的）：

| 现象 | 根因 |
|---|---|
| 升级卡住不动，最后报错退出 | 安装器改名安装目录时被占用，Windows error 32 |
| 提示「无法安装，另一个程序正在使用此文件」 | DSH 进程没杀干净 |
| 升级后 DSH 打不开 | 新版本有问题，但没有自动回滚 |
| AI 代跑升级，跑到一半断掉 | AI 进程在 DSH 进程树内，杀 DSH 会连带杀死自己 |
| 官方 feed 版本号滞后，明明有新版本却提示「已是最新」 | feed 更新不及时 |

## 二、全部问题清单（按发现顺序）

### 第一阶段：真机环境暴露的问题（v4 初版 → v4.3）

#### 问题 1 · 【致命】AI 代跑时脚本自杀

**现象**：让 AI 帮忙跑升级，跑到「阶段3 清理进程」就断掉，DSH 停在半装状态。

**根因**：脚本是 DSH 的子进程。杀 DSH 时，Windows 会把子进程一起杀掉。

**修复**：新增 `Test-InDshTree` 函数，沿 `ParentProcessId` 向上走 15 层，判断自己是否在 DSH 进程树内。如果在，就用 `schtasks /Create /SC ONCE /ST 23:59 /RU <当前用户> /RL HIGHEST` 创建独立计划任务再 `/Run`，子进程父级会变成 `svchost.exe`，彻底脱离。

用 `-DetachedChild` 参数 + 环境变量标记避免无限递归。

**验证**：实测 `child_in_dsh_tree=False`。

---

#### 问题 2 · 备份漏文件导致回滚后插件不匹配

**现象**：回滚到旧版本后，插件报版本不兼容。

**根因**：原版只备份 `package.json` / `cordis.yml` / `cordis.patch.yml` 三个文件，漏了 pnpm 的配置。

**修复**：备份清单补齐 `pnpm-workspace.yaml` 和 `pnpm-lock.yaml`，共 5 个文件。

---

#### 问题 3 · TEMP 堆满导致安装器解压失败

**现象**：安装器退出码 2，日志报 `extract-failure`。

**根因**：本机 TEMP 堆了 5000+ 条目，安装器要解压 7892 个文件时 7-Zip 失败。

**修复**：阶段1 加 TEMP 预检，条目数 > 1500 时清理 7 天前的旧残留和 `nsu*.tmp`。

---

#### 问题 4 · 残留目录清理不全

**现象**：升级后安装目录旁边堆了一堆 `DeepSeek Harness.new-{GUID}` / `.broken-xxx` 垃圾目录。

**根因**：原版只清 `.old-` 前缀。

**修复**：覆盖 `.old-` / `.new-` / `.upgrade-probe` 三种，`.broken-` 保留最近 1 个用于排错。

---

#### 问题 5 · 日志中文乱码

**现象**：日志里的中文变成乱码。

**根因**：PowerShell 5.1 的 `Add-Content -Encoding UTF8` 会写 BOM，多次追加时中文被 ANSI 码页误读。

**修复**：改用 `[System.IO.File]::AppendAllText` + `UTF8Encoding($false)` 无 BOM 追加。

---

#### 问题 6 · 窗口正常却被误判回滚

**现象**：DSH 明明正常启动了，工具却自动回滚到旧版本，白升一次。

**根因**：原逻辑「3 分钟内有 crash 日志就回滚」，但历史遗留的 host 崩溃记录（如插件报 `CODEX_AUTH_REQUIRED` 后重启过一次）会被误算。

**修复**：记录 `$installFinishedAt`，只统计**升级完成之后**新产生的 `crash-*-main.log` / `crash-*-host.log`，且要求窗口仍稳定。

---

#### 问题 7 · 【严重】大小写误判

**现象**：版本比较偶尔出错。

**根因**：PowerShell 的 `-eq` 对字符串**大小写不敏感**，`'RC.2'` 和 `'rc.2'` 被判相等，跳过后续有序比较。

**修复**：改用 `-ceq`（区分大小写）。SemVer 规范要求预发布标识按 ASCII 序比较。

---

#### 问题 8 · 进程已死却还在等

**现象**：DSH 已经退出了，工具还在傻等 90 秒。

**根因**：`Wait-DshWindow` 里用 `$i -gt 20`（约 10 秒）才开始判断「进程已死」。

**修复**：改为 `deadRounds` 连续 6 轮（约 3 秒）进程不存在就提前退出。

---

#### 问题 9 · 重复运行互相干扰

**现象**：不小心双击两次，两个实例同时跑，互相杀进程。

**修复**：`Global\DSH-AutoUpgrade-SingleInstance` 互斥锁，已被占用就 `exit 21`。

---

#### 问题 10 · 参数拼错静默忽略

**现象**：写了 `-NotARealParam`，脚本照常运行、exit 0，用户以为生效了。

**根因**：PowerShell 用 `-File` 调用时，**未知参数会被静默忽略**。

**修复**：param 块之后立即检查 `$args.Count`，有未知参数就打印中文用法清单 + `exit 22`。

---

#### 问题 11 · 日志英文看不懂

**修复**：日志级别标签全部汉化 —— `[OK]→[成功]`、`[WARN]→[注意]`、`[ERROR]→[失败]`、`[STEP]→[步骤]`、`[INFO]→[信息]`。启动横幅的 `强制重装=是/否` 也汉化。

### 第二阶段：虚拟机环境暴露的问题（v4.4 → v4.9）

> 这一段是**最有价值的部分**。在 Hyper-V 虚拟机（Win11 专业工作站版）里跑真实升级，暴露出 6 个真机上根本发现不了的 bug。

#### 问题 12 · 【严重】无 GPU 环境被误判启动失败

**现象**：虚拟机里升级成功，但工具判定「窗口和 Web 服务均未就绪，判定启动失败」，触发自动回滚。

**根因**：Hyper-V 虚拟机用 `Microsoft Hyper-V Video` 虚拟显卡，**没有真实 GPU**。Electron 在这种环境下会自动降级为 **Web 模式**运行：
- 服务正常，能返回完整界面 HTML
- 但**不创建任何窗口**（连 `EnumWindows` 都查不到，`MainWindowHandle=0`）

旧逻辑只检测窗口句柄，所以必然误判。

**修复（v4.4）**：新增 `Test-DshWebAlive` 函数。窗口没出现时，探测 DSH 主进程是否在监听本地高位端口且可访问：
1. 收集 DSH 进程 PID
2. `Get-NetTCPConnection -State Listen` 筛选这些 PID 监听的端口
3. 只探测 ≥ 1024 的端口（避免误判系统端口）
4. `Invoke-WebRequest` 请求 `http://127.0.0.1:<port>/`
5. HTTP 200 + 内容含 `<html` → 健康
6. **HTTP 401/403 也算健康**（只是缺 token，服务活着）

**实测**：虚拟机里 rc.1 → rc.2 升级成功，Web 服务端口 51177 监听，HTTP 200 返回 41,916 字节完整界面 HTML。

---

#### 问题 13 · 【严重】`-Force` 重装同版本被误判失败

**现象**：rc.2 → rc.2 强制重装，安装器退出码 0、实际装好了，但脚本因为「版本没变」判为失败，**又白跑一次安装**（多耗 3 分钟）。

**根因**：成功判定只认「版本升高」（`Compare-SemVer > 0`）。同版本重装时版本本来就不变。

**修复（v4.5 → v4.8 演进）**：
- v4.5：加 `isSameVersionReinstall` 判定
- v4.8：发现 `-Force` 在 feed 滞后时目标版本可能**低于**当前版本（rc.2 → rc.1），降级也是 `-Force` 的正常语义，旧逻辑同样不满足
- **最终方案（v4.9）**：判成功的唯一标准改为「装完后版本 == 目标版本」，升级 / 同版本重装 / 降级三种情况统一适用

---

#### 问题 14 · 【严重】安装超时后不清理，把环境搞坏

**现象**：第 2 次安装 180 秒超时后判定失败，但**版本被降级到 rc.1**。

**根因**：超时后只打了一句 `Write-Log '安装器超时' 'WARN'`，**进程和残留都没清**，安装目录停在半损坏状态，第 2 次重试叠加在坏环境上。

**修复（v4.6）**：超时后强制执行 4 步清理：
1. 杀掉本次安装器进程（`$proc.Kill()`）
2. 杀掉同名残留进程（NSIS 常留子进程）
3. 清理 `.new-` / `.tmp-` / `.upgrade-probe` 残留（绝不碰正式安装目录）
4. 检查 exe 是否丢失，丢了就告警

---

#### 问题 15 · 【致命】`$host` 是只读内置变量，Web 探测从未生效

**现象**：v4.4 加了 Web 探测，但虚拟机里**永远判定启动失败**，日志显示 `Test-DshWebAlive` 返回 `$null`。

**根因**：`Test-DshWebAlive` 里写了 `foreach ($host in @('127.0.0.1'))`，但 **`$host` 是 PowerShell 的只读内置变量**（`ConsoleHost`），赋值直接抛：

```
无法覆盖变量 Host，因为该变量为只读变量或常量。
```

而该异常又被外层 `catch {}` **静默吞掉** —— 所以探测函数每次都走到 `return $null`，**v4.4 的修复从来没真正工作过**。

**修复（v4.7）**：变量改名为 `$probeHost`。

**实测**：修复后 Web 探测 **1 秒内命中**（90s 等窗口 + 1s 探测）。

---

#### 问题 16 · 【致命】回滚后健康检查只看窗口

**现象**：回滚成功（rc.1 已恢复），但判定「回滚后窗口未在 90s 内出现」→「自动回滚未成功，需要人工介入」。

**根因**：`Restore-FromBackup` 里回滚后的健康检查同样只看窗口，没走 Web 探测。虚拟机里必然失败。

**修复（v4.7）**：回滚后窗口没出现时，同样调 `Test-DshWebAlive`。

**实测日志**：
```
[注意] 回滚后窗口未在 90s 内出现，改查 Web 服务模式...
[成功] 回滚成功（Web 模式运行，端口 64964，HTTP 401），版本 0.2.2-rc.2
```

---

#### 问题 17 · 【致命】回滚都失败了却报「升级成功」

**现象**：
```
[失败] 自动回滚未成功，需要人工介入
[成功] 结果   : 升级成功          ← 自相矛盾！
```
退出码还是 0。用户会以为升级成功，实际环境是坏的。**这是最危险的假绿**。

**根因**：回滚失败分支只打日志，**没有把 `$pass` 置为 `$false`**，汇总时 `$pass` 仍是阶段6 留下的 `$true`。

**修复（v4.7）**：
1. 回滚失败时 `$pass = $false`
2. 新增 `$rollbackFailed` 标记
3. 汇总新增分支：`结果 : 升级失败，且自动回滚也失败，需要人工介入`
4. 新增退出码 **7**

---

#### 问题 18 · 【致命】函数定义在调用之后，`-RollbackOnly` 永远失败

**现象**：`-RollbackOnly` 跑 4 秒就返回 `exit 6`（失败），**日志零线索**——连 `New-Section '自动回滚'` 都没打印。

**根因**：**PowerShell 是顺序执行的**。
- `-RollbackOnly` 块在**行 169** 调用 `Restore-FromBackup`
- 但 `Restore-FromBackup` 函数定义在**行 367**
- 调用时函数还不存在 → 抛 `无法将"Restore-FromBackup"项识别为 cmdlet、函数...` → 被吞掉

**修复（v4.9）**：把 `-RollbackOnly` 整块移到所有函数定义之后。

**验证方法**：写了对照实验，确认 PowerShell 的行为：

| 场景 | 结果 |
|---|---|
| 顶层直接调用未定义函数 | ❌ 报错 `The term 'X' is not recognized` |
| 函数体内部引用后定义的函数 | ✅ 正常（函数体在**调用时**才解析） |

所以只有**顶层调用**需要严格保证顺序。

---

#### 问题 19 · 【致命】`Test-DshWebAlive` 也在调用之后定义

**现象**：修完问题 18 后发现 `Restore-FromBackup`（行 381）内部调用 `Test-DshWebAlive`，但后者定义在**行 1081**（文件末尾）。

**根因**：同一个顺序问题。虽然函数体内部引用是调用时解析，但 `Restore-FromBackup` 被**顶层** `-RollbackOnly` 调用时，内部的 `Test-DshWebAlive` 必须已经定义。

**修复（v4.9）**：把 `Test-DshWebAlive` 整个函数移到文件最前面（所有函数之前）。

**全量审计结果**：13 个函数全部顺序正确。

---

#### 问题 20 · 【致命】`$target` 是对象不是字符串

**现象**：版本明明已达目标（当前 `0.2.2-rc.2`，目标 `0.2.2-rc.2`），却判「版本未达到目标」，又白跑第二次安装。

**根因**：`$target` 是 **PSCustomObject**（含 `Version` / `Source` / `Url` 属性），不是字符串。v4.8 里写成了：

```powershell
Compare-SemVer $vNow $target        # ❌ 传对象
```

`Split-SemVer` 收到对象后当成空版本处理 → 永远返回 `-1` → 判「未达到」。

**修复（v4.9）**：所有比较一律用 `$target.Version`，共修正 11 处调用。

**验证**：单测 6 个用例全过（正常升级成功 / 同版本重装成功 / 降级成功 / 升级失败 / 降级失败 / 安装器退出码非0）。

---

#### 问题 21 · 【严重】回滚时杀进程不彻底，且错误被静默吞掉

**现象**：`-RollbackOnly` 反复失败，日志零线索。

**根因**：`Restore-FromBackup` 第 1 步杀进程写的是：

```powershell
foreach ($p in $ps) { try { $p.Kill() } catch {} }
```

两个问题：
- `Kill()` 是**异步**的，立即检查「进程数=0」常常还没退干净就往下走
- 杀失败的错误被 `catch {}` **静默吞掉**，日志完全看不出为什么失败

实测真实原因：进程占着安装目录，导致改名报「另一个进程正在使用此文件」。

**修复（v4.9）**：
1. `Kill()` 后加 `$p.WaitForExit(5000)` 等待退出
2. 失败时记录 `结束进程失败 PID=x: <原因>`
3. 剩余进程时逐个打印 `仍在运行: PID=x`
4. 改名重试从 3 次增加到 4 次
5. **第 2 次改名失败时用 `taskkill /F /T /IM` 强杀整棵进程树兜底**

| **22** | 未知参数 | 检查命令行拼写 |

## 四、参数说明

| 参数 | 作用 | 什么时候用 |
|---|---|---|
| （无参数） | 查最新版 → 升级 | 日常升级 |
| `-Silent` | 静默安装（NSIS `/S`） | 不想看安装界面 |
| `-Force` | 目标版本 ≤ 当前版本也强制装 | 修复安装 / 强制降级 |
| `-ProbeLatest` | 主动探测 bin 目录更高版本 | feed 滞后时（工具默认已开） |

| `-NoStart` | 安装后不启动 DSH | 想自己控制启动时机 |
| `-InstallerPath <路径>` | 跳过下载，用指定安装包 | 已经手动下好了 |
| `-DetachedChild` | 内部用，标记已脱离进程树 | 不要手动加 |

## 五、使用说明

### 方式一：双击启动（推荐给不熟悉命令行的）

双击 `一键升级-v4.bat`，出现中文菜单，按数字选择即可。

### 方式二：命令行

```powershell
# 日常升级
powershell -NoProfile -ExecutionPolicy Bypass -File "DSH-AutoUpgrade-v4.ps1" -Silent

# 先看看会发生什么（不下载不安装）
powershell -NoProfile -ExecutionPolicy Bypass -File "DSH-AutoUpgrade-v4.ps1" -DryRun

# 升级出问题，退回上一版
powershell -NoProfile -ExecutionPolicy Bypass -File "DSH-AutoUpgrade-v4.ps1" -RollbackOnly

# 修复安装（强制重装当前版本）
powershell -NoProfile -ExecutionPolicy Bypass -File "DSH-AutoUpgrade-v4.ps1" -Force -Silent
```

### 方式三：让 AI 代跑

直接把脚本路径给 AI，它会自动检测自己在 DSH 进程树内，用计划任务脱离后执行。**不需要手动关 DSH**。

## 六、注意事项（踩过的坑）

### 关于脚本文件本身

1. **`.ps1` 必须是 UTF-8 带 BOM**
   含中文的 PowerShell 脚本缺 BOM 会产生大量语法错误（实测 59~79 个），完全跑不起来。
   判断：`[IO.File]::ReadAllBytes($f)[0..2]` 是否为 `239,187,191`。
   自愈：`bom-guard.ps1` 会自动修复。
   注意：**多数编辑器（包括 `edit` 工具）保存时会丢 BOM**，改完必须重新检查。

2. **`.bat` 必须是 UTF-8 无 BOM + CRLF 行尾 + 首行 `chcp 65001`**
   三条缺一即失败：
   - 缺 `chcp 65001` → 中文乱码
   - 带 BOM → BOM 被当命令的一部分
   - LF 行尾 → 整行被拆碎，报 20+ 条 `'xxx' is not recognized`

3. **不要把长 PowerShell 命令塞进 `.bat`**
   引号转义极易出错，拆成独立 `.ps1` 由 bat 调用。

### 关于 PowerShell 的坑

4. **`$host` / `$HOME` / `$PID` 等是只读内置变量**
   赋值直接抛错。曾因此让 Web 探测功能整整一个版本没生效。
   同类危险变量：`$error`、`$args`、`$input`、`$matches`、`$PSItem`。

5. **函数必须定义在使用之前（顶层调用）**
   PowerShell 顺序执行。函数体内部引用是**调用时**解析，但顶层直接调用必须是已定义状态。

6. **`-File` 调用时未知参数被静默忽略**
   拼错参数名不报错、照常运行、exit 0。必须自己检查 `$args.Count`。

7. **`catch {}` 空捕获会掩盖致命问题**
   本次有 2 个 bug（问题 15、21）都是因为 `catch {}` 吞掉了异常，导致日志零线索、排查耗费大量时间。
   **建议**：关键路径的 catch 至少记录 `$_.Exception.Message`。

8. **`$target` 这类变量要确认是字符串还是对象**
   直接把 PSCustomObject 传给字符串函数不会报错，会静默返回错误结果。

### 关于升级过程

9. **杀 DSH 前先判断自己在不在它的进程树内**
   否则脚本会自杀。用 `Test-InDshTree` 或 `schtasks` 脱离。

10. **`Kill()` 是异步的**
    杀完必须 `WaitForExit()` 或轮询确认，否则后续操作会撞上「文件被占用」。
    顽固进程用 `taskkill /F /T /IM` 整棵树强杀。

11. **虚拟机 / 无 GPU 环境下 DSH 不建窗口**
    Electron 自动降级为 Web 模式，服务正常但没有窗口。
    **不能只用窗口句柄判断健康**，必须探测 Web 端口。

12. **官方 feed 会滞后**
    `nightly.yml` 里的版本号可能比实际可下载的旧。工具默认开 `-ProbeLatest` 主动探测。

13. **`-Force` 允许降级**
    当 feed 版本低于当前版本时，`-Force` 会真的降级。这是设计语义，不是 bug。
    不想降级就别加 `-Force`。

### 关于数据安全

14. **升级只碰程序目录，不动用户数据**
    明确保护：`~/.dsh/sessions`、`attachments`、`.credentials.yaml`、`storages`、`skills`、`integrations`、`rewind-snapshots`、`profiles/desktop/node_modules`。
    只备份程序目录 + 5 个配置文件。

15. **备份保留最近 2 份**
    更早的自动清理。备份在 `C:\dsh-rollback\`。

## 十、已知限制

1. **虚拟机 GUI 无法通过 PowerShell Direct 观察**
   只能读文本输出、退出码、进程/窗口/端口枚举。界面是否正常显示需人工确认。

2. **`-RollbackOnly` 只回滚最近一份备份**
   想回滚到更早的版本需手动从 `C:\dsh-rollback\` 复制。

3. **无 GPU 环境固定走 Web 模式**
   这是 Electron 的行为，不是工具能改变的。用浏览器打开 `http://127.0.0.1:<端口>/` 即可使用。

4. **feed 与 probe 双来源**
   probe 只能探测到 bin 目录里真实存在的版本号，无法发现尚未上传的版本。
