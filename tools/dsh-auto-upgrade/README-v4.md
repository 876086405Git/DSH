# DSH 全自动升级工具 v4（本机适配版）

> 基于 v3 改造，针对本机实测问题修复。**16 轮严格自检 + 最终回归 14/14 通过**。

## 快速使用

双击 `一键升级-v4.bat` → 选 `1` → 等它跑完。

启动器会先自动检查 `.ps1` 的 UTF-8 BOM（丢了会自动补回），再进入菜单。

## BOM-GUARD（启动器内置）

`.ps1` 含中文，PowerShell 5.1 只在文件带 UTF-8 BOM 时才能正确解码。
若用某些编辑器或 AI 工具改过该文件，BOM 会丢失 → 中文变乱码 → 实测产生 **59 个语法错误** → 脚本起不来。

`一键升级-v4.bat` 每次启动前会自动检测并补回 BOM（纯 ASCII 逻辑，不会自身失效），
已实测：删掉 BOM → 语法错 59 个 → 跑一次启动器 → BOM 恢复 → 语法错归零。

## 三项常见发布风险（实测结论）

| 风险 | 本机实测结果 | 处理 |
|---|---|---|
| **行尾符** | `.bat` 若为 LF 行尾，cmd 会把每行拆成碎片，实测报 20+ 个 `not recognized`，**整个启动器完全跑不起来** | 已强制 `.bat` 为 **CRLF + 无 BOM**；`.ps1` 保持 LF（PowerShell 兼容） |
| **网络封锁标记** | 给 `.ps1`/`.bat` 打上 `Zone.Identifier`（ZoneId=3）后，`-ExecutionPolicy Bypass` 仍能正常执行 | 本机不构成问题；`bom-guard.ps1` 仍会自动 `Unblock-File` 做兜底（更严格的企业策略下有用） |
| **中文路径** | 把工具整个放到 `中文测试目录\升级工具\` 下，bat 菜单正常、ps1 退出码 0、中文无乱码 | 无需处理，可放心放在任意中文路径 |

### 文件编码规范（维护时务必遵守）

- `DSH-AutoUpgrade-v4.ps1` → **UTF-8 带 BOM**（含中文，PS5.1 必需）
- `bom-guard.ps1` → **UTF-8 带 BOM**（含中文注释）
- `一键升级-v4.bat` → **UTF-8 无 BOM + CRLF 行尾**（三条同时满足才能跑）

> 用编辑器或 AI 工具改过 `.ps1` 后 BOM 会丢，双击启动器即可自动修复。
> 但改过 `.bat` 后务必检查行尾是否被转成 LF——这会让启动器彻底失效。

### 中文显示的技术要点（维护必读）

`.bat` 里显示中文需要**三条同时满足**，缺一即乱码或无法运行：

| 要求 | 说明 |
|---|---|
| `chcp 65001` 在首行 | 切到 UTF-8 代码页，必须在任何中文输出之前 |
| 文件为 UTF-8 **无 BOM** | 带 BOM 会把 BOM 字节当命令 |
| 行尾为 **CRLF** | LF 行尾会让 cmd 把整行拆碎，完全跑不起来 |

实测对比：UTF-8+chcp 65001 显示正常；GBK(936) 两种写法都乱码。

## v4.4 新增（虚拟机 / 无 GPU 环境支持）

Hyper-V 虚拟机用的是 `Microsoft Hyper-V Video` 虚拟显卡，**没有真实 GPU**。
Electron 在这种环境下会自动降级为 **Web 模式**运行：服务正常、能返回完整界面 HTML，
但**不创建任何窗口**（连 `EnumWindows` 都查不到）。

旧逻辑只检测窗口句柄，会把这种情况误判为「启动失败」并触发自动回滚。

**修复**：窗口没出现时，再探测 DSH 主进程是否在监听本地高位端口且可访问（HTTP 200 或 401），
能访问则同样判定为健康，并提示用浏览器打开。

实测：虚拟机里 rc.1 → rc.2 升级成功，Web 服务端口 51177 监听，HTTP 200 返回 41,916 字节完整界面 HTML。
