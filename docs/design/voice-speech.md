# 朗读、语音输入与语音通话

2026-11-13 DeepSeek 开放平台发布了语音接口（[语音合成](https://api-docs.deepseek.com/zh-cn/guides/tts)、[语音识别](https://api-docs.deepseek.com/zh-cn/guides/asr)，参考实现 [deepseek-ai/chat-demo](https://github.com/deepseek-ai/chat-demo) 的 `src/services/speech/`）。这份设计把它接进 dsh-go：默认用用户登录的 DeepSeek 账号付费，免配置；每个地方都能换成别的渠道。

## 1. DeepSeek 给了什么

| | 语音合成 `POST /v1/tools/tts` | 语音识别 `POST /v1/tools/asr` |
|---|---|---|
| 输入 | JSON：`text`（≤1 万计费字符，汉字算 2）、`voice_id`（`stella` 海星女声 / `tide` 暗潮男声）、`format`、`filter_markdown` | multipart 的 `file`：16 位 PCM WAV 或 Ogg Opus，≤8 MiB、≤120 秒 |
| 输出 | 边合成边返回；`pcm` 是 24 kHz 16 位单声道裸流 | 整段返回 `{text, duration_ms}`，不支持流式 |
| 另有 | WebSocket 流式合成（边喂文字边出音频） | — |
| 价格（限时 5 折） | 1.5 元 / 万字符 | 0.39 元 / 小时 |
| 限速 | 每账号 50 并发 | 同左 |

不能调语速、没有中断续传、识别没有中间结果。

## 2. 谁付钱：凭据怎么走

- **登录的账号**：token 只在引擎里（`deepseekAccount.resolveToken(url)`，对推理源返回 token，请求头 `x-dsh-auth-token`，见引擎 `dsh-web-search-deepseek`）。App 拿不到也不该拿到，所以由 bridge 代发：`/dsh-go/v1/speech`（合同见第 7 节，实现 `runtime/bridge/dsh-go-bridge/lib/speech.js`）。
- **API Key**：设置里填的 DeepSeek Key，App 直连 `api.deepseek.com`，音频边到边播。
- **主机的 Key**：主机配了 Key 但 App 没填时，也走 bridge。bridge 用引擎自己的 `credentials.resolve('DEEPSEEK_API_KEY')` 取值（引用名可用 bridge 配置 `speech.apiKeyEnv` 改），每次请求现取，不缓存、不记录。账号被上游拒绝时不会自动换 Key 重试（免得多扣一次）。

顺序：账号 → App 的 Key → 主机的 Key → 都没有就提示「先登录或填 Key」。bridge 的能力探测按连接缓存 2 分钟（`deepseek_speech.dart`）。

**还没验证的**：真实上游是否接受 `x-dsh-auth-token` 调 `/v1/tools/*`。文档只写了 Bearer API Key。真机登录后第一件事就是验它；不接受时账号路线返回 `speech/sign-in-required`，App 提示改用 Key。

## 3. 朗读（每条回复下）

- 主对话：回复动作行加**朗读**键（待机喇叭 → 请求中转圈 → 播放中变停止），长按菜单也有。酒馆：长按角色消息的菜单。
- 同一时间只读一条；发新消息、切对话、开通话都会停（`read_aloud.dart`）。
- 读之前在 App 里去掉代码块、表格、图片、链接地址和格式符号（`speakable()`）；DeepSeek 那边也开着 `filter_markdown`。
- 切片：第一片到第一个句末且不少于 8 字就发（尽早出声），之后约 120 字一片、最长 300 字；下一片在上一片播放时就去请求（最多提前 2 片）。
- DeepSeek 的声音：PCM 写进**一条**原生流（`SpeechPlugin.kt` 的 `PcmStream`，AudioTrack 流模式，约 400 ms 缓冲），片与片之间没有缝。其他声音（手机自带、预设服务、OpenAI 兼容、自定义 HTTP）沿用伙伴小屋的逐句取文件、顺序播放。

## 4. 语音输入

识别方式从三种变成五种：**自动**、**DeepSeek**、**系统**、**语音模型**、**其他云端服务**（OpenAI 兼容 `/audio/transcriptions`：Whisper、硅基流动 SenseVoice 等）。

- **自动**：有人付钱（账号或 Key）就用 DeepSeek；否则照旧（语音模型就绪用它，再否则系统识别）。录音会上传，所以自动模式第一次用到 DeepSeek 时提示一次，带「更换」。
- 云端识别都是录完整段再识别（`WavRecorder` 16 kHz WAV），录音上限 118 秒（DeepSeek 120 秒）。代价是没有边说边出字；要实时出字的人可以选系统识别。
- 伙伴小屋、酒馆、主对话三处的听写控制器都接上了同一个 `voiceCloudProvider`；桌宠的严格离线模式不变。

## 5. 设置

- 原「语音输入」页改名**语音**，分区：朗读（**朗读的声音**）、识别方式、云端识别服务（选了「其他云端服务」才出现）、语音模型、语音通话。
- **朗读的声音**就是伙伴小屋「她的声音」那一页（`CompanionVoicePage(shared: true)`）：去掉开关和克隆声音，来源多一个 DeepSeek（海星 / 暗潮），默认 DeepSeek。存储键独立（`speech_voice_*`）。
- 伙伴小屋「她的声音」的来源多了**跟朗读一样**（新用户默认）和 **DeepSeek**；**以前配过的人保持原样**（存过设置、没有 `follow` 字段的视为自己选的）。她的声音开关仍默认关：她每句都读，默认开会悄悄花钱。

## 6. 语音通话

入口：输入框加号里的**语音通话**（新对话也能直接打，第一句话会建对话）。页面盖在对话上，深色，像打电话。

```
采集（VOICE_COMMUNICATION + 回声消除 + 降噪）→ 说话检测（SpeechGate：自适应噪声底、迟滞、700 ms 拖尾）
→ 停顿后整句（含开口前 300 ms）交给识别 → 当普通消息发进对话
→ 回答流式到来就按句喂给朗读（同第 3 节，播放走通话音频）
→ AI 说话时你开口：两段式打断（见下）
```

- 通话期间：音频切到通话模式，默认免提，有耳机用耳机；屏幕常亮；占用 App 唯一的麦克风（`MicArbiter`，插件的听声会先让出）。
- 识别：按识别方式的设置找一个能识别录音的（系统识别不行）：选定的云端 → DeepSeek → 引擎语音模型；都没有就结束并说明。
- **已登录却付不了语音**（2026-11-14 用户反馈「明明登录了还提示缺语音渠道」）：账号语音要走主机上的桥接（`/dsh-go/v1/speech`），1.0.16 及更早的运行环境里没有这条路由，经 DSH Remote 中继时也走不了。这时不再提示「先登录 DeepSeek 账号」，而是说明是这次连接用不了账号付费，给出填 API Key / 下载语音模型的办法（`DeepSeekSpeechFailure.accountUnusable`）；通话里 DeepSeek 的声音没人付费时，她改用手机自带的声音照常说话。用旧运行环境打的测试包都会这样，要换成带新桥接的运行环境才能用账号付语音。
- **口语回答**（默认开）：通话的第一条消息前面加一句「这是语音通话……请简短口语化回答，不要用 Markdown」。这句和下面「告诉模型听到哪」那句都包在 `<dsh-note>` 里随消息发出：模型看得到，对话、编辑重发、导出分享里都不显示（`state/app_notes.dart`；DSH 没有「只给模型看」的字段，只能这样）。
- 要批准或回答问题时，卡片直接出现在通话页（复用伙伴小屋的 `CompanionAsk`）。
- 短于 350 ms 的声音不算话（咳嗽、敲桌）；识别为空不发。轻点光球跳过当前这段回答（只是不读，回答照常写完）。
- **两段式打断**（语音 v2 第一期，参照火山 RTC、Vapi、LiveKit、OpenAI Realtime 的做法）：
  - **先压低**：AI 说话时你一开口，原生侧马上把她压到约 −12 dB，不停播。系统朗读（`SpeakerOut`）压不了音量，就照旧马上停。
  - **再决定**：
    - 你说到 1.6 s 还没停，算接过话头：停播，并停止这一轮生成。
    - 1.6 s 内说完，就看识别结果：「嗯 / 对 / 好的 / ok」这类附和、噪声、空白，她恢复音量接着说；「停 / 等一下 / 别说了」让她停，但不发消息；别的话让她停，这句话作为下一条消息发出（词表在 `speech/call/turn_words.dart`）。
  - **告诉模型听到哪**：被打断的回答，按实际播放进度（原生每 40 ms 的播放回报）算出你听到了哪里，下一条消息前附一句「你说到「…」时我打断了你，后面的我没听到」。DSH 的历史改不了，只能这样告诉模型。
- **端上判停**（语音 v2 第二期，`nativemedia/NeuralGate.kt`）：
  - 判开口：Silero VAD v6.2，概率超阈值 120 ms 算开口；她在说话时阈值更高，要持续 200 ms。
  - 判说完：smart-turn v3.2，停顿 200 ms 就看最近 8 秒判断说完没有。说完了立刻结束（原来要等 700 ms）；没说完就继续听，静音满 3 s 强制结束。
  - 两个模型随 APK（约 11 MB），用 ONNX Runtime 跑，判停推理在工作线程。
  - 加载不了时退回原来的能量门；某次停顿判停推理出错，这次停顿按能量门的 700 ms 结束，日志记一次。
- **实时字幕**（第三期，`ui/speech/call/call_live.dart`，后端见 [streaming-asr.md](streaming-asr.md)）：
  - 设置 › 语音 › 实时字幕里可下载流式识别模型（约 198 MB，sherpa-onnx 中英 zipformer，只在手机上跑）。只有字幕和插话判断在手机上；选了云端识别，录音照样上传给它。
  - 下载后，通话时从同一路收音分出 PCM 给它，你说话时字幕一边说一边出。
  - 她在说话时你插话，实时识别到 4 个字以上、又不是附和，就不等 1.6 s 直接接过话头。
  - 说完后字幕先显示手机识别的结果，云端结果到了再替换；发给 AI 的仍是上面选的识别方式给出的文字，手机模型的准确率不如云端。
  - 解码跟不上时最多排 1 秒的帧，再多的新音频丢掉，字幕不会越拖越晚。
  - 听写也用它：录音时草稿里先出手机识别的字，录音的识别结果到了再替换；识别失败、为空或太短时草稿恢复原样。
  - 没下载就跟以前一样。
- **第一句早开口**（2026-11-14）：回答的第一段说到逗号（，、：；或后面跟空格的英文逗号、冒号）就送去合成，只要够 8 个字；以前要等第一句说完。后面的段落照旧按句子合成。1,000、3:30 这种数字里的符号不算停顿。
- **通话里改声音和识别**：右上角「通话设置」（原「通话背景」，齿轮）里多了「她的声音」「识别方式」两项，点进去就是设置里的那两页；改了从下一句开始生效（声音每段回答前重新读，识别方式一改就换）。
- **停顿多久算说完**（2026-11-15）：用户反映稍一停顿她就接话。以前静下来 0.2 秒就问判停模型，它说「说完了」就发；现在模型说完了也要等够所选的停顿才算：快 0.2 秒（即以前）、适中 0.6 秒（默认）、耐心 1.2 秒；不管模型怎么说，静够 3 / 3.5 / 5 秒一定算完；没有模型时（能量门）静 0.7 / 1 / 1.6 秒算完。设置里和通话设置里都能选，通话中改了下一次停顿就按新的算（`callPause`）。
- **字幕跟着声音走**：通话页的回答字幕按她说到的位置出，不按文字到达的速度出；声音还没出来时不显示，跳过或朗读失败时显示整段。一句的音频还没合成完时，按慢速朗读估它的长度，播放追上合成也不会一下算成整句听完。
- **字幕区**（2026-11-14 改版）：你说的话最多 3 行（还在说时大一号、亮一些，她开口后退成小一号的灰字），她的回答最多 5 行；更长时顶端渐隐，最新的字留在下面，宽度占满两侧留白（平板上最宽 560）。字幕多了中间的光跟着缩小让位（最小 56 %），字幕区高度变化是平滑的。她说完后最后几个字的淡入会补满（以前末尾 8 个字一直半透明）。
- **全部字幕**：左上角「字幕」键或轻点字幕区，弹层列出这次通话的每一轮（你的话靠右、和聊天里的气泡一样，她的回答靠左；被你插话打断的注明「你在这里插话」），说着话时实时更新、停在底部就跟着滚。数据是 `VoiceCallController.turns`。
- **不弹横幅**：通话开着时，它的对话算「正在看」（`callChatProvider` → `viewedChatProvider`），回复完成、审批、提问都不再弹顶部横幅（审批和提问本来就显示在通话页里）；别的对话完成照常弹。通话页关掉后清掉。
- **思考提示音**（默认开，设置 › 语音 › 语音通话）：你说完 1.2 s 还没有一个字的回答，就轻响一声，两个柔和的正弦音（E5、B5，约 −20 dBFS），每轮最多一次。只在回答文字到来之前放，因为原生侧只有一条播放流，开提示音会顶掉她的声音。
- **画面**（`ui/speech/call/call_visuals.dart`，学 Siri 但更克制；默认，2026-11-14 用户定。背景面板的「光效」里还能换成 Libraries.dev 的光环或细线）：一颗通透的玻璃球，里面几团柔光慢慢流动（走非匀速的曲线），边上一圈细光，屏幕四周有很淡的同色流光。颜色从主题色取：主色左右几个相邻色相，低饱和、偏浅，蓝主题就是蓝紫青，绿主题就是绿青，不会是彩虹。浅色/深色跟主题走：浅色是磨砂玻璃配浅底，深色是清透玻璃配深底；背景是图片或伙伴时始终按深色。动起来靠三种节奏：一直在的呼吸（吸气快、呼气慢、末尾停一下，周期略有漂移，等待时约 5 秒一口，思考时变快变浅，有声音时让位给声音）；说话的音节和重音（每 40 ms 的音量，`level` 跟音节起落，`accent` 只在音节突然变响时冒一下）；语势（近一秒的平均音量，定流速）。用户说话时色斑往里收、随音节轻轻鼓起；它说话时色斑随音节往外放、鼓得更明显；静音变灰变慢。系统开了「移除动画」时颜色不流动、不呼吸、不错落入场，只保留大小随声音变。全用 CustomPainter，不用着色器。（2026-11-14 用户先后否了「花里胡哨」的深海光球和「艳俗、晃眼、不通透」的彩虹版。）
- **背景**：右上角可换**深海**（默认的深色底）、**我的图片**（模糊、压暗，字幕看得清）、**伙伴**（伙伴小屋的角色以 bare 模式站在深色底上，`mood` 跟着通话状态走，`mouth` 每 50 ms 跟一次声音大小）。设置 › 语音里也能改。
- **切到后台通话就结束**：Android 不给后台 App 麦克风，硬撑只会录到静音。要后台通话得加麦克风类型的前台服务，留作后续。

## 7. bridge 合同（`/dsh-go/v1/speech`，能力名 `speech`）

1. `GET /dsh-go/v1/speech` → `{"v":1,"credential":"account"|"api-key"|null}`，不发上游请求。
2. `POST /dsh-go/v1/speech/tts`，JSON `{text, voice}` → `200 application/octet-stream`，边收边转上游 PCM；App 断开时中止上游；上游中途断开就销毁响应。
3. `POST /dsh-go/v1/speech/asr`，体是音频（`audio/wav` / `audio/ogg`，≤8 MiB）→ `{text, duration_ms}`。
4. 错误 `{"error":{"code","message"}}`：`speech/no-credential` 401、`speech/sign-in-required` 401、`speech/unauthorized` 401、`speech/insufficient-balance` 402、`speech/rate-limited` 429、`speech/rejected` 400、`speech/too-large` 413、`speech/busy`（上游的 5xx 原样带回）、`speech/upstream-unreachable` 502。不记录、不回显凭据。

旧引擎没有这组路由时，探测失败按「没有账号路线」处理，App 的 Key 照常可用。

## 8. 没做 / 后续

- 后台通话（前台服务）、蓝牙耳机 SCO 的细调、听筒模式贴脸熄屏。
- DeepSeek 的 WebSocket 流式合成：现在按句切片 + 预取已经够快，WebSocket 能让句间语调更连贯，等真机听感再定。
- 伙伴小屋里的「通话模式」（Live2D + 真实口型 + 免手动发送）：通话控制器不依赖页面，接一个伙伴版的 `CallConversation` 即可。
- iOS：Dart 层通用，`dsh/speech` 要另写原生实现。
- 延迟没实测。估计从说完到出声 2.5–3 秒，瓶颈是识别不流式。
