# 她会留意你的通知（伙伴小屋 · 主动能力，2026-11-23）

用户的话：「Mika 的『主动能力』收集通知之类的，我感觉可以加给小屋伙伴。」

## 0. 学 Mika 什么、改什么

Mika（a40f6a98 的 `proactive/`）读你选定 App 的通知，用轻量模型把每批判成「值得提醒 / 记下 / 忽略」，在悬浮胶囊上写「N 条值得提醒」，你点开才在一个对话里列出来；再慢慢归纳出你关心的话题和常联系的人，按 App 的档位决定能不能带进任务。它反复强调「不会不等你开口就自己说话」。

值得抄的：

- 只读你**点名的 App**，不在名单里的连内容都不读；锁屏不读，解锁后把通知栏里还在的补收。
- 每个 App 一个档位（不读 / 只提醒 / 还能记住）；丢掉进度条、播放器、来电、闹钟、导航这类系统通知，丢掉验证码。
- 通知原文进模型时包成「不可信内容」，判定不带工具、拿不准就忽略；按 App 凑批、冷却、失败退避、每天上限。
- 从通知里记下的东西标明「不是你说的」；每一条都能追到出处，能删、删了就不再记。
- 页脚把发给模型的是什么、存了什么、存多久讲清楚。

DSH Go 的伙伴不一样的地方——她是**一个人**，不是工具，所以：

- **她可以主动开口**，但用她自己的节奏：走已有的「她多主动」配额（`companion_initiative.dart`，夜里不说话、一天几次、隔多久），通知只是她多了一个「看到的事」，不另开一套推送。
- **用她的口吻说**，不列清单：「你妈妈刚在微信里问你周末回不回家，要不要我帮你回一句？」——问你要不要帮忙，而不是替你做。
- **记下的东西进她的记忆**（`companion_memory`），走记忆管家同一套，标来源「从通知看到的」，在记忆页能看到、能删；默认不进「关于你」的长期档案，只当近况（7 天后淡出），除非你在聊天里确认了。
- **帮你回**只在你点头之后，走「帮你操作手机」（4e）现有的手机工具和确认，不新开回复通道（Android 通知的快捷回复也不用——那等于不经确认替你发）。

## 1. 用户看到的

### 1.1 开关和权限

伙伴小屋 › 设置 › **她会留意你的通知**（默认关）。

- 打开时先问通知使用权（系统页）；没授权时开关下写「还差一步：允许 DSH Go 读取通知」+ 去授权。
- 下面是**她看哪些 App**（默认一个都没有）：列出最近 7 天发过通知的 App（图标 + 名字 + 发过几条），每个一个档位：
  - **不看**（默认）
  - **看一眼**：只用来决定要不要告诉你，看完就忘
  - **会记住**：值得记的近况记进她的记忆
- 常用推荐（微信、QQ、短信、日历、邮件、快递类）排在前面，但不预选。

页脚三句（照实写）：「通知会发给你给她配置的模型（现在是 DeepSeek），只发你选的 App 的。原文不存，只存她记下的那几句近况，在记忆页能看到、能删。锁屏时她不看。」

### 1.2 她怎么说

- 判成**值得说**的，进她的「想说的话」：你在小屋里时她直接说；不在时，若开了「她一直在」，在她的悬浮体 / 常驻通知上冒一句（一句话，带 App 名，不带原文全文）；都没开就等你下次进小屋时说。
- 配额：和她平时主动开口共用「她多主动」的额度，另外通知引起的每天最多 6 次，同一个人 / 同一件事 2 小时内不重复；深夜（她的作息）只攒着不说。
- 你回「帮我回一下」「好」之类，她起草回复给你看，你点头后走 4e 去发；你说「别管」就这件事不再提。
- 判成**记下**的（只在「会记住」的 App）：静默记进近况，不打扰。她以后聊天时自然会用到（「你上次说快递到了，拿了吗？」）。

### 1.3 她看到了什么

记忆页里多一个筛选「从通知看到的」：每条近况写着出处（App · 时间），可以删；删了这件事她不再记。另有「全部清掉」。

## 2. 后端（交给 Pro）

- **采集**：`NotificationListenerService`，组件默认禁用，开关打开时启用。只收名单里、档位不是「不看」的 App；丢掉 ongoing / 进度 / 播放器 / 来电 / 闹钟 / 导航 / 计时器 / 前台服务类，丢掉含验证码、密码字样的（复用 `SensitiveWords`）；去掉不可见字符、截断到 500 字。锁屏时请系统解绑，解锁后重绑并补收通知栏里还在的。微信这种同一键反复重发的，按键保留最近 10 段文字。
- **收件箱**：只在内存（引擎进程 / 伙伴常驻服务里），上限 200 条，判定后即丢原文。
- **判定**：用她的模型单独调一次，不带工具。每批只放一个 App、最多 8 条、凑 20 秒；原文包在不可信标记里；返回 `say`（她想说的一句话，用她的口吻、不超过 60 字，按 `companion_context` 的人设生成）/ `remember`（一句近况）/ `ignore`，拿不准就 ignore。同一通知键判过有冷却；失败退避 2 / 5 / 15 / 30 分钟；每天请求上限 300 次。
- **送达**：`say` 交给 `companion_initiative` 作为一种新的信号（`notice`），由它按配额、作息、你在不在决定何时说；`remember` 交给记忆管家写近况（来源 `notice`，7 天淡出）。
- **帮你回**：她的回复里带一个「帮你回」意图时，走 `companion_agent_phone_tools` 现有的路（打开那个 App 的那个对话、输入、发送前确认）。
- **原生 ↔ Dart**：`dsh/companion` 通道加 `notices.status`（授权、开关、各 App 档位、今天收到 / 判定 / 说了几次）、`notices.setEnabled`、`notices.setLevel {pkg, level}`、`notices.recentApps`（最近 7 天发过通知的 App 和条数），事件 `noticeSignal`。

## 3. 不做

- 替你自动回复、快捷回复。
- 话题 / 联系人归纳、日报周报（Mika 有；她的记忆管家已经在做「了解你」，不再开第二套）。
- 敏感类推断（健康、财务、宗教……）：判定提示里明确不记这类。
- iOS（没有通知读取）。鸿蒙另说。

## 4. 第一波实现与验收口径

第 1 节保留界面交互目标。本波提供 Android 后端与 Dart 接口。字段、错误码与记忆页调用见[界面接入对照](companion-notices-interface.md)。设置入口、推荐 App 排序和记忆页筛选由界面改动接入。iOS 和鸿蒙本波均没有通知监听器。

### 4.1 Android 实际能看到什么

`NoticeListener` 是系统绑定、默认禁用的组件，与小屋和缓存的 Flutter 引擎同属 Android 主进程。开启开关会启用组件，缺少通知使用权时打开系统设置。开着开关、授了权、设备已解锁且屏幕可交互，才观察本用户的通知。App 列表从开启并获授权后开始累积，只显示最近七个本地日历日观察到的包及计数，允许先列出尚未点选的 App。只有选了“看一眼”或“会记住”的包才会读取通知字段和 extras。DSH Go 自己的通知不进入列表或判定。

过滤 ongoing、前台服务、进度、媒体、通话、闹钟、导航和计时类通知；先在完整可见字段检查验证码、密码等词，再把去重、清理不可见字符后的每段截到 500 个 Unicode 码点。收件箱限 **200 个通知键**，同键按到达顺序留最近 10 段，相邻重复段合并。每段分别带系统发布时间和可选的会话标识。原文、原始系统键和联系人标题均不写磁盘。

#### 已知限制

关掉“她一直在”，监听器仍可工作；它不会为判定启动 Flutter 或新建保活服务。没有小屋或常驻接手时原文暂存在该进程内。锁屏时清空待判原文、停止取件并请求系统解绑，进程仍在时由应用级解锁广播请求重绑。只有系统确认重连才补收通知栏中仍然存在的记录。如果解绑期间进程被回收，解锁当刻无法保证重绑；后续打开应用或系统再次连接时才能补收，当时已撤下的内容无法恢复。系统依据见 Android 的 [NotificationListenerService](https://developer.android.com/reference/android/service/notification/NotificationListenerService) 与[隐式广播例外清单](https://developer.android.com/develop/background-work/background-tasks/broadcasts/broadcast-exceptions)。

### 4.2 一次判定和两种结果

| 时点 | 实现行为 |
| --- | --- |
| 取件 | 有可用小屋/常驻处理者和伙伴的 DeepSeek API Key 才开始。同包第一条入队满 20 秒后可一次取最多 8 键，期间新来的同包键也可入批；同键一次派发后冷却 2 分钟。如果取走后请求失败，该批原文即丢，后续批依次退避 2、5、15、30 分钟。 |
| 模型请求 | 复用轻量伙伴的模型、用量回执和后台费用预算。每天最多派发 300 次。人设进系统提示，App 名称、档位和各段文字进入不可信 JSON 包装，提示词资源为 `app/assets/companion/notice_triage.md`。本次请求没有工具。 |
| 返回校验 | 返回项只能指向本批已有的键序号和段序号。用于提醒的短句须包含 App 名且最多 60 个码点。判定拒绝复制原文的输出。“记下”仅接受会记住档位中有限的日常事务类别，并对来源及结果做敏感检查。词表与模型判断都不能保证识别所有自然语言中的敏感含义。 |
| 记忆 | `remember` 写入同一份伙伴 SQLite 的 `recent` 近况，来源含 App、所选段的时间和“未经本人确认”。观察时间满七天后停止向聊天模型提供正文和出处；卡片留在记忆页供查看、删除。维护回合无法召回这些来源或以它们整理长期档案。本人后来在普通对话中明确说的内容可以成为独立证据。 |
| 删除 | 单条删除、“别管”和清除全部通知近况会保留被删事件的安装级指纹，阻止同一 App 相同规范化内容再次入库。独立卡片即使措辞相同也不会连带删除；换一种通知措辞或换一个 App 不能保证识别为同一现实事件。 |
| 开口 | `say` 进入现有 initiative。未送达的摘要在内存里最多保留到所选段发出后 24 小时；夜间、额度不足、没有可展示处都要等待。小屋使用已有主动开口入口，常驻使用已有提示途径。常规频率与间隔照常生效，通知另限滚动 24 小时最多 6 次。按通知标题里的来源人或会话与 App 的组合，两小时内只提醒一次。来源标题为空或只有 App 名时丢弃这条提醒。同键的两个已知不同会话、或不同 App 的同名联系人，分别计算，仍受共同开口间隔约束。 |

系统键、用于阻止重记的事件内容、用于会话去重的标题均使用本安装范围内的带密钥摘要。标题可能是群名，同一人跨 App 的身份没有可靠对应关系。最近 App 计数、日期/时间水位、额度、冷却和费用回执是本机元数据。小屋不会把参考通知写出的即时回答或回复草稿写入 App 聊天历史、提取队列或伙伴记忆。已送达 Android 常驻通知的文字沿用现有通知展示规则；只要这条系统通知仍在，后续可从中重建最近的展示记录，最多 8 条，包括已显示的摘要或草稿。因而第 1.1 节页脚还需要交代“本机会保存 App 计数、用量和防重复所需的标识”；对原文的本机保留规则不代表模型服务商的保留承诺。

### 4.3 回复和通道

用户紧接着一个实际展示过、带帮回意图的提醒说“帮我回”或“好”，先取得无工具草稿。草稿须完整生成并收到真实显示回执，随后本人明确确认，才能进入已有手机工具流程，发送前仍按原生确认规则处理。目标 App 中具体对话不清楚时要问本人。中间换话题、锁屏、撤权、关闭、离开或换角色会使原有确认失效。已展示的草稿最多可在 10 分钟内接续确认。常驻界面只以文字展示参考了通知的回复和草稿：`_presentLine` 收到 `noticeEpoch` 后，在文字送达时结束，避免语音预热跨过锁屏后再朗读。普通回复沿用原有的语音设置。系统通知的快捷回复不参与。

| `dsh/companion` 方法或事件 | 参数与返回 |
| --- | --- |
| `notices.status` | 返回 `enabled, granted, unlocked, levels, received, judged, said, epoch, consentEpoch`。今天的三个计数分别是入箱、完成判定的键、实际送达的提醒；按本机日期重算。 |
| `notices.setEnabled` | `{enabled: bool}`，返回最新状态。系统设置页面返回后再读实际授权。 |
| `notices.setLevel` | `{pkg, level}`，level 为 `off`、`glance`、`remember`；未列出的包按 `off`。返回最新状态。 |
| `notices.recentApps` | 返回 `[{pkg, name, count, icon}]`，图标为可空 PNG 字节。 |
| `noticeSignal` | 原生只发 `{epoch}` 唤醒或使旧任务失效，不附正文。Dart 主动拉取待处理键，最后取件/送达前重新校验状态。 |

内部 `notices.pending` 只返回包、键指纹和入队时间。`notices.takeBatch` 以包、键和 `epoch` 从内存一次性取走分段内容。`notices.record` 以当时的 `epoch` 记判定或送达数。锁态和授权变化使 `epoch` 失效；`consentEpoch` 在开关、授权、任一档位变化或进程重建时轮换。单纯锁屏不会使已判摘要永久失效，撤权后再授权不会复活此前的待办。

纯 JVM、Dart/SQLite 测试覆盖部分规则与迁移。系统授权面板、不同厂商重绑、真实 App 的发帖行为以及实际手机操作确认需单独验收。见[Android 真机验证清单](../testing/companion-notices-device.md)。
