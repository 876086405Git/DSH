# dsh-go 宠物系统设计

> 2026-10-25。本文是宠物系统实现规格的正式版，相对规格改过的地方集中列在 §12。
> 素材：Deepy 小鲸鱼（Clawd on Desk 主题包）、鲸娘（dshtui.com 序列帧），源文件在 `app/tool/pet_src/`，作者与授权见仓库根目录的 `ASSETS.md`。

## 0. 结论

- **协议与 Clawd on Desk 一致。** 状态名、事件对应、优先级、一次性与持续态的划分都沿用 Clawd，两套素材因此可以直接用。Codex Pet 留到第二期，作为导入格式。
- **宠物是状态指示器，不是养成游戏。** 它只表达 agent 在干什么、有没有事等你，不设饥饿、好感之类的数值，不主动调模型、不独立联网；「问一句」由用户触发，复用聊天发送链路。dsh-pet 每 5 分钟调一次模型说话，是我们明确不做的反例。
- **一屏一个吉祥物。** 宠物站在活动条上时接管鲸尾；空状态里的静止鲸尾在宠物开启时也隐藏。
- **同一件事只提醒一次。** 宠物在屏幕上时，它的气泡替代现有的玻璃横幅。当前正在看的对话不冒气泡，只做动作。后台照常发系统通知。
- **不挡事。** 命中区只算身体，避开「回到底部」按钮，输入框弹出层打开时让位，列表底部为宠物留出高度，悬浮窗空闲时原地变淡。
- **像素必须清楚。** 每个美术像素对应整数个**物理**像素，位置也对齐物理像素。尺寸按身体高度分小、标准、大三档，另有「自定义」（见 §2.10 下的说明）。
- **悬浮窗做成可降级的可选项。** 默认关闭，用户打开时再申请权限。被拒、被系统藏起、被 ROM 杀掉，都退回 App 内宠物加系统通知，不报错。

### 1.2 落到我们身上的原则

1. **反应多，主动少。** 宠物的动作几乎都是对 agent 事件或用户触摸的回应。主动行为只有待机小动作和游走，而且很稀疏。
2. **只在有事时说话。** 气泡只用于做完、出错、等你确认或回答这四类事，且同一件事只说一次。没有闲聊，没有提醒你回来。
3. **随手能藏，处处能关。** 长按菜单里有「藏起来 1 小时」。悬浮窗拖到底部就关，设置里一键「不显示」。
4. **不挡事。** 不挡输入框、按钮和正文，不抢焦点，不劫持触摸。
5. **小而清楚。** 标准档身体高约 30dp，像素边缘清晰。
6. **省电是默认行为。** 不在屏幕上就不画，待机时停在静帧，只在帧号变化时重绘。

## 2. 产品规则

### 2.1 入口与默认值

- 设置 › 主题里加一组「宠物」，点进去是宠物页。宠物页包含：
  - 选宠物：Deepy 小鲸鱼、鲸娘、不显示，带实时预览；
  - 大小：小、标准、大、自定义（选自定义时下面展开预览和滑条）；
  - 安静模式；
  - App 外显示；
  - 作者与来源，作为页底一行小字。
- 默认值：Deepy 小鲸鱼、标准大小、站在输入框上。安静模式关，App 外显示关。
- 第二期再做导入 Clawd on Desk 主题 zip 和 Codex Pet zip，§3.5 先把映射定好。

### 2.2 站位（perch）

- **站位**是聊天页里一组水平的胶囊上沿：输入框，以及它上方的活动条、待办条、目标条。各个胶囊用 key 向 `PetPerch` 注册表上报自己。宠物永远站在**当前最上面那条可见胶囊**的上沿，脚踩着边。
- **脚线**：`anchor.baseline` 乘以缩放倍数后，必须落在胶囊上沿上，误差不超过 0.5 逻辑像素。跟随时用 `CompositedTransformFollower` 挂在胶囊的 `LayerLink` 上，不要逐帧读 `GlobalKey` 的矩形。逐帧读会晚一帧，键盘升起的动画里看得出脚离开了边。
- **换站位**：条出现或消失时，宠物播 hop 跳到新的上沿，水平位置按比例保持。hop 的时长和曲线走 `AppMotion`。
- **默认水平位置在左边 1/4 处。** 右侧是「回到底部」按钮和待确认胶囊的位置（`chat_list.dart`，右下、输入框上方 12dp）。
- **禁区**：「回到底部」按钮或胶囊可见时，它的矩形左右各外扩 8dp，作为禁区。宠物不站进禁区，拖进去松手会吸附到禁区外最近的位置。按钮出现时如果宠物正好在禁区里，它会走开。
- **拖动**：拖动时播 drag 动画，松手后吸附到当前站位，位置按比例存起来。
- **让位**：以下几种时候宠物淡出，不占命中区：斜杠面板、@ 提及、附件面板或语音面板打开时，多选或编辑模式，只读对话。这些弹出层关闭后再淡入。
- **不挡正文**：宠物开启时，聊天列表的底部内边距加上宠物在站位之上的高度，即 `contentBox` 顶到 `baseline` 的距离乘以缩放倍数。这样滚到底时，最后一行字不会被宠物盖住。
- **命中区**：只算当前动画的命中框（§3.2 的 `hitBoxes`），框外的触摸全部穿透给下面的列表和按钮。

### 2.3 一屏一个吉祥物

- 宠物开启并站在活动条上时，活动条里的鲸尾隐藏，鲸尾的位置收起，文字左移，左右内边距保持对称。宠物的动作接替鲸尾表达状态。
- 宠物开启时，空状态里的静止鲸尾（`empty_state.dart:170`）也隐藏。宠物本身就站在输入框上，不需要两条鲸鱼。
- 宠物关闭或藏起来时，鲸尾原样回来。

### 2.4 待机、游走、睡觉

- **待机**：按 `idlePool` 的权重和时长随机播放待机动作。Deepy 的 `idle-follow.svg`（眼睛跟随鼠标）在手机上不用，待机用 `idle.apng`。
- **游走**：
  - 平均 2 分钟一次，间隔在 45 秒到 5 分钟之间随机，只在空闲时触发；
  - 沿当前站位走一小段，不进禁区，不越出胶囊两端，按方向翻转；
  - 输入框有焦点、列表正在滚动、或者有气泡在显示时，都不游走。
- **睡觉**：处于空闲状态，并且 App 里 60 秒没有任何触摸时，宠物入睡。任何触摸或事件都会叫醒它：先播 waking，再进入应有的状态。
- **减弱动效**：系统关闭动画时，`AppMotion` 的时长为零。这时宠物停在每个状态的首帧，换站位直接瞬移，不游走，不播 hop。

### 2.5 互动（App 内）

| 手势 | 反应 |
|---|---|
| 单击身体左半、右半 | 分别播 `tapLeft`、`tapRight` 反应，播一遍后回到原状态 |
| 1.1 秒内连点 3 下 | 挠痒痒（`tickle`）；连点期间继续点会延长 |
| 继续连点到 6 下（仍在 1.1 秒内） | 包里有 `annoyed` 反应时播它，并清空点击计数；没有就继续播 `tickle` |
| 按住并移动超过 6dp | 拖动，播 `drag`，松手后吸附 |
| 长按 | 小菜单：换宠物、藏起来 1 小时、宠物设置 |
| 宠物在 notification 状态时单击 | 不播戳的反应，改为执行「去看看」：当前对话就滚到待确认的卡片，别的对话就打开那个对话 |
| 宠物在睡觉时单击 | 只叫醒，不播戳的反应 |

挠痒痒从规格的「连点 4 下」改成「1.1 秒内 3 下」，和鲸娘原页一致。手机上的目标很小，连点 4 下容易点偏。第 4、5 下仍在挠痒痒里，第 6 下才算「烦了」：包里有 `annoyed` 就播它并清空计数（下一次点又从头开始），没有就继续播 `tickle`。

### 2.6 气泡提醒（App 内）

现有的提醒分三路（`notify_state.dart` 的 `deliveryFor`）：正在看的对话不提醒，前台时出玻璃横幅，后台时发系统通知。宠物接进来以后：

| 场景 | 现在 | 有宠物以后 |
|---|---|---|
| 事件发生在正在看的对话里 | 不提醒 | 不冒气泡，宠物只做动作：attention、error、notification。待确认事项继续由「回到底部」胶囊承担；单击宠物等同于点那个胶囊 |
| 前台，别的对话，聊天页可见，宠物可见，非安静模式 | 玻璃横幅 | **宠物气泡替代横幅**，同一件事不出两次 |
| 前台，别的对话，但不在聊天页、宠物藏起来或安静模式 | 玻璃横幅 | 不变 |
| 后台 | 系统通知 | 不变；悬浮窗开着时另见 §2.7 |

为此 `AlertDelivery` 要加一个 `pet` 值。条件全部满足时，原本该出横幅的提醒改走宠物。

气泡规则：

- **内容**：一行，正文只有四种：「做完了」「出错了」「等你确认」「等你回答」。别的对话的事件在前面加标题，写成「标题 · 做完了」。标题先过 `secret_mask`，超过 12 个字截断。
- **合并**：2 秒内来了多件事，合成一个气泡，例如「3 个对话做完了」。等你确认或回答的事优先显示，同时只保留一个待显示的气泡。
- **停留**：做完了 4 秒，出错了 6 秒，等你确认或回答 8 秒。确认或回答之前，宠物会一直保持 notification 动作。点按会提前收起；向上轻扫会收起，但不跳转。
- **点按**：打开那个对话，并滚到对应的审批卡或问题卡。
- **不提醒的事**：被停下的轮（`stopped`）、压缩完成、连接断开都不提醒。
- **可访问性**：气泡带 `liveRegion` 语义，读屏会念出来，能聚焦，也能点。宠物本体是装饰，不进语义树。因为气泡替代了横幅，它必须做到横幅原有的可访问性。

### 2.7 App 外悬浮窗

**什么时候出现**

- **默认模式「有事时显示」**：App 在后台，并且有对话正在跑或者有事等你时，悬浮窗出现。App 回到前台时它隐藏，舞台交还给聊天页上的宠物。
- **「一直显示」模式**：只要 App 不在前台就显示。
- **自动收起**：最后一件事结束 5 分钟后，如果没有新事件，悬浮窗收起。「一直显示」模式不自动收起。
- **其他情况**：灭屏时暂停；锁屏时系统本来就不显示这类窗口。敏感界面（例如权限对话框、银行 App）可以调用 `setHideOverlayWindows(true)` 把悬浮窗藏掉，这时我们等它重新可见，不报错，也不重复添加窗口。

**交互**

| 手势 | 行为 |
|---|---|
| 拖动 | 跟手移动，松手后吸附到最近的屏幕左边缘或右边缘，纵向位置记住 |
| 拖到屏幕底部中央的「×」 | 今天不再显示。这个「×」只在拖动时出现，和聊天头像的做法一样 |
| 单击 | 逗它：像素宠物按身体左右半播 `tapLeft`、`tapRight`；悬浮窗里是伙伴时走小屋的轻点反应（见 companion-floating.md）。头三次单击弹一条「连点两下打开对话」，双击过一次后不再弹 |
| 连点两下 | 打开最相关的对话，见下文。判定用系统的双击时限和容差；无障碍的点击动作直接打开 |
| 长按并滑动 | 朝内展开半轮盘；滑向功能后松手执行，滑回宠物身上或轮盘外松手取消；原地松手则轮盘留着等点选。无障碍长按可直接点选 |
| 无活动后空闲 10 秒 | 活动期间（`PetPush.active`）保持常亮；活动结束后开始计时，重复空闲状态推送不延长。空闲满 10 秒原地变淡到 60% 不透明度，整只留在屏幕内，照常能点能拖，动画暂停；碰一下、新气泡、有结果或有请求时恢复 |

**最相关的对话**，按以下顺序取第一个：

1. 等你确认或回答的对话（等得最久的那个）；
2. 刚出错还没看过的对话；
3. 刚做完还没看过的对话；
4. 正在跑、最近有动静的对话；
5. 最近看过的对话。

由 Dart 端算好，随状态一起推给 Kotlin，Kotlin 只负责调用 `EntryActivity.openChat`。

**气泡**

- 文案和合并规则同 §2.6。悬浮窗气泡只显示标题，从不显示对话正文。
- 气泡是单独的一个小窗，显示期间可以点，收起后窗口移除。
- 位置和 App 内一致：放在**当前画面的上方**，即身体框并上当前动画的帧格，跳起来的身体、思考云、「!」都在气泡下面，不会钻到气泡后面。宁可比只按身体框高出一截（Deepy 的 happy 约 21 个美术像素，标准尺寸下约 80 物理像素），也不盖住宠物。横向仍是内侧边缘和身体对齐、朝屏幕中间伸，尾巴指向身体中线。换动画时气泡跟着新画面在 200ms 内平滑移过去，不跳。
- 上方放不下（贴在屏幕顶部时）就放到画面侧面、朝屏幕中间的一边，和身体中线等高，尾巴横着指回宠物；侧面也放不下才放到画面下方。任何情况下都在屏幕安全区内，不压状态栏和导航栏。实现见 `EdgeSnap.bubble`。
- **悬浮气泡仅在完整显示批准内容时提供「允许本次 / 拒绝」。** 2026-10-30 的「问一句」扩展取代原先一律不提供按钮的规则，具体边界见 §14。App 内气泡仍只打开对应卡片。

**与系统通知的关系**：系统通知照常发，数量不减。悬浮窗可见、亮屏、气泡没关时，「做完了」和「出错了」这两类通知改为静默（不弹横幅、不响，`ResultSilence`），因为悬浮窗气泡会说一遍。「等你确认」和「等你回答」保持原样。

这样一来，气泡就是这一刻唯一的提醒，宠物在后台必须看得到这一轮结束。聊天页把当前对话的状态告诉宠物（`_FocusReporter`）时走 provider 订阅，不靠页面重建：App 在后台时 Flutter 不出帧，靠重建会让宠物以为对话还在跑，把「做完了」当成新一轮开始吞掉，通知又是静默的，两头都没有提醒（2026-11-01 修复，`test/pets/pet_focus_background_test.dart`）。

**行为边界**

- 悬浮窗不游走，只在原地播动作。在别的 App 上空走来走去就成了 Desktop Goose。
- 不抢焦点，不弹 Activity，不在别的 App 上自动展开任何东西。

### 2.8 安静模式与隐藏

- **安静模式**：只做动作，不冒气泡，App 内和悬浮窗都适用。原本该由宠物气泡承担的提醒，退回玻璃横幅或系统通知，提醒本身不会丢。
- **藏起来 1 小时**：期间不显示，鲸尾回来，提醒走原来的横幅；1 小时后自动出现。
- **今天不再显示**：只针对悬浮窗，到次日 0 点恢复。

### 2.9 网页模式

网页模式的聊天页里没有原生宠物。用户可以在网页里自己装 dsh-pet（风险见 §1.1 的对比表）。悬浮窗在两种模式下都工作，数据都来自同一个 `PetMood`。

### 2.10 尺寸

- 尺寸按**身体高度**定档，不按画布大小，这样两只宠物看起来一样大：

  | 档位 | 身体目标高度 |
  |---|---|
  | 小 | 22dp |
  | 标准 | 30dp |
  | 大 | 40dp |

  身体高度取 `contentBox.h`。
- 缩放倍数 `k` 的定义是：每个美术像素占多少个**物理像素**。像素画包要求 `k` 为整数：先算 `max(1, round(目标dp × devicePixelRatio ÷ contentBox.h))`，再让小、标准、大**至少各差 1**（`medium = max(small + 1, …)`，`large = max(medium + 1, …)`）。不加这一步的话，dpr 2.75 的手机上 22/30/40dp 会同时落成 1/2/2，三档分不出大小，悬浮窗还会比 App 内小一档。
- 「自定义」（2026-11-15）：身体高度 15–90dp，即标准的 50%–300%，滑条按标准的 5% 一格，显示为百分比。它单独取整 `max(1, round(高度 × dpr ÷ contentBox.h))`，不参与三档的「至少差 1」。拖动时只重画设置页里的预览，松手才保存（`pet.custom_height`），聊天页和悬浮窗随之更新；切回三档时这个高度留着，下次选自定义还在。悬浮窗收到 `size: custom` 和 `bodyHeight`，在原生侧变成 `custom:<dp>` 这个尺寸键，高度变了就重新载入贴图。用处是有的宠物包按 `contentBox` 定档后看起来还是偏小或偏大。
- 非像素画包（`pixelArt: false`）的 `k` 不限整数：`k = 目标dp × devicePixelRatio ÷ contentBox.h`。
- 宠物的左上角和脚线都对齐到物理像素。
- 悬浮窗和 App 内用同一档位，也就是同一套 `k`：App 内是 `pet_sprite.dart` 的 `petDevicePixels`，悬浮窗是 Kotlin `PetPack.devicePixels`，两边各有一份逐值对齐的单测（`pet_pixel_test.dart`、`PetPackTest.kt`）。

### 3.2 pack.json（schema 1）

下面是 `deepy-whale` 的实际内容（`animations` 只列一段，`frames` 截短）。完整格式、每个字段的解析规则以 `app/lib/pets/pet_pack.dart` 为准，生成工具是 `app/tool/make_pet_pack.py`。

```json

  "id": "deepy-whale",
  "name": "Deepy 小鲸鱼",
  "author": "DSH-TUI",
  "license": "DSH-TUI 吉祥物，作者授权 dsh-go 使用",
  "source": "DSH-TUI（Clawd on Desk 主题包 v1.0.0）",
  "pixelArt": true,
  "scale": 5,
  "canvas": {"w": 52, "h": 52},
  "anchor": {"x": 28, "baseline": 48},
  "contentBox": {"x": 12, "y": 26, "w": 36, "h": 22},
  "hitBoxes": {
    "default": {"x": 12, "y": 26, "w": 33, "h": 22},
    "wide": {"x": 8, "y": 18, "w": 44, "h": 31},
    "sleeping": {"x": 7, "y": 23, "w": 39, "h": 25},
    "byAnim": {

             "frames": [{"i": 0, "ms": 50}, {"i": 1, "ms": 50}, {"i": 2, "ms": 50}]}
  },
  "idlePool": {
    "everyMs": {"mean": 120000, "min": 45000, "max": 300000},
    "anims": [{"anim": "idle-look", "ms": 6800, "weight": 1}, {"anim": "idle-spout", "ms": 6400, "weight": 1}]

  "states": {
    "idle": ["idle"], "thinking": ["thinking"], "working": ["typing"], "juggling": ["music"],
    "error": ["error"], "attention": ["happy"], "notification": ["notification"],
    "sweeping": ["compacting"], "carrying": ["carrying"],
    "sleeping": ["sleeping"], "waking": ["waking"], "roam": ["roam-hop"]
  },
  "bonus": {},
  "tiers": {
    "working": [{"min": 3, "anim": "building"}, {"min": 2, "anim": "music"}, {"min": 1, "anim": "typing"}],
    "juggling": [{"min": 2, "anim": "conducting"}, {"min": 1, "anim": "music"}]
  },
  "timings": {
    "minDisplay": {"attention": 5200, "error": 4800, "sweeping": 5600, "notification": 3200,
                   "carrying": 3200, "working": 1000, "thinking": 1000},
    "autoReturn": {"attention": 5200, "error": 4800, "sweeping": 300000, "carrying": 3200},
    "wakeMs": 1500
  },
  "reactions": {"tapLeft": "react-left", "tapRight": "react-right",
                "tickle": "react-double", "drag": "react-drag"},

  "sleep": {"afterMs": 60000}

```

字段说明（相对规格新增或改动的字段标 ★）：

- ★ **`scale`**：源图相对逻辑像素的倍率，总是写出来。缩回 1 倍无损才存 1 倍，否则保留原倍率。
  - 鲸娘是 1。
  - Deepy 是 5：身体画在半像素上，呼吸和压扁按 1/5 像素变化，缩回 1 倍会丢细节。
- ★ **`anchor`**：`baseline` 是脚线，即身体最低不透明行的下沿，放到站位胶囊的上沿；`x` 是身体水平中心，也是镜像轴。
  - Deepy 是 48 和 28，不是 Clawd 主题写的 48.5 和 27。48.5 是阴影的中线，阴影落在脚线下方，压在胶囊上做接触阴影；27.75 是待机各帧质心的平均。
  - 鲸娘是 60 和 35.5。
- ★ **`cols`**：一张图里每行放几帧，默认等于帧数，也就是单行横条。约束：
  - 每张图的任一边不超过 4096 物理像素；
  - 单段动画解码后建议不超过 8 MB。Deepy 有 6 段例外（8.8～12.9 MB），保持 5 倍无损；
  - Deepy 一段最多 68 帧：5 倍时单行宽 17,680 像素，会超过很多 GPU 的纹理上限。所以保持 5 倍，用网格排列（`cols`）并去重。
- ★ **`box`**：每段动画的帧格只裁到这段动画实际有像素的范围，`box` 是帧格贴回画布的位置（逻辑像素）。`frameW = box.w × scale`。
- **`frames`**：每项是 `{i, ms}`，`i` 指向图里的第几格。相同的帧只存一格，靠 `i` 重复引用。Deepy 是统一 20fps，持帧多，去重能省下不少。
- ★ **`hitBoxes`**：结构与 Clawd 的分类一致：`default`、`wide`、`sleeping` 三类框，加上 `byAnim` 单独给框，单位是逻辑像素。两个包的框都从帧里量出来，不沿用主题：
  - 每帧只取最大的一块连通区域当身体，思考云、Zzz、音符这类脱离身体的道具不算；
  - 一段动画里至少 25 % 时间是身体的格子，才算进这段的身体框；
  - 超出 `default` 较多的动画进 `wideAnims`；离 `default` 太远或被拎起来的，在 `byAnim` 里单独给框；
  - 每段动画查到的框至少框住它 90 % 的身体。
  - 查找顺序：`byAnim` → `sleepingAnims` → `wideAnims` → `default`。
- ★ **`idlePool`**：随机待机，是对象：
  - `everyMs` 是插播间隔：平均 120 秒，最短 45 秒，最长 300 秒，只在空闲且可见时计时；
  - `anims` 是待机池，每项带时长和权重。
  - 基础待机循环在 `states.idle[0]`，不放进池子。
  - 时长都是整 2 遍：Deepy 的取值与 Clawd 的 `idleAnimations.duration` 一致，鲸娘按原页的循环时长算。
- ★ **`bonus`**：每个非 idle 状态进入时按 `chance` 抽一次彩蛋，抽中就先播这一段（`playMs` 或一遍的时长），播完回到该状态的主动画。idle 的小动作由 `idlePool` 管，不走 `bonus`。包里没给某个状态写 `bonus`、而 `states.<状态>` 还有别的动画时，按 1/3 概率抽其中一段。鲸娘的 `smile-hearts`、`thumbs-up` 放在 attention 下，概率 0.2；Deepy 没有彩蛋，写 `{}`。
- ★ **`reactions`**：反应名（`tapLeft`、`tapRight`、`tickle`、`annoyed`、`drag` 等）→ 动画名。每个反应可以有多个动画，跨版本的写法是「基础名 + 编号」：
  - `"tickle": "a", "tickle2": "b", "tickle3": "c"`：旧版 App 只读基础名、忽略带编号的键，照样能玩；当前 App 在基础名存在时把 `tickle2`、`tickle3`… 按出现顺序并进 `tickle`，每次播放随机抽一段（`reaction()` 取第一项，`reactionOutOf()` 抽一项）。
  - 基础名不存在时，带编号的键保留成独立反应（`reaction('tickle2')` 仍可读），不会被静默丢掉。
  - `"tickle": ["a", "b"]` 这种数组只在 App 内可读；导出和市场规范化都会降级成上面的编号写法，不能把数组当作跨版本分享格式。
  - 需要在状态外保持固定姿势的地方（如拖动时的 `drag`）只读第一项。
  - 空数组等于没写这个反应，不报错；数组或编号键里有一项不是已有动画名时整包拒绝。
- ★ **`roam.faces`**：美术本身朝哪边，取 `"left"`、`"right"` 或 `"front"`。它取代含义不清的 `flip`。
  - `left`、`right`：往反方向走时以 `anchor.x` 为轴镜像。Deepy 的 `roamFlipAssets: true` 表示美术朝左，所以是 `left`。
  - `front`：正面，不镜像。鲸娘是 `front`，镜像会把发花和尾巴换边。
- **`timings`**：
  - Deepy 的取值与 Clawd 主题一致，只去掉 notification 的 `autoReturn`。
  - 鲸娘按原页事件表的保持遍数换算：error 1 遍，1480ms；happy 2 遍，3040ms；carrying 2 遍，2240ms；waking 1 遍，1880ms；notification 3 遍，2640ms，只作 `minDisplay`。
  - 鲸娘的压缩动画在原页里一直保持到下一个事件，没写遍数，所以 sweeping 的 `minDisplay` 取 1 遍，1740ms。
  - notification 不设 `autoReturn`，见 §4。
  - working / thinking 的 1000 是去抖，sweeping `autoReturn` 的 300000 是保险上限，两个包一样。
- **缺省字段的回退**（旧包和手写包不必写全新字段）：
  - `states` 没写的状态播 `states.idle[0]`；缺 `tiers` 时按该状态的主动画播，不分档；
  - 没写 `bonus` 时该状态没有彩蛋（`states.<状态>` 有第二段动画时按 1/3 概率抽其中一段）；没写 `idlePool` 时待机小动作取 `states.idle` 第二段起的动画；
  - 没写某个 `reactions` 键时对应的点按静默跳过，不报错也不崩；没写 `hitBoxes` 时用 `contentBox` 当命中区，没写 `timings` 时用默认时长。
- 状态名一律用 Clawd 的。动画名用包自己的：鲸娘的反应叫 `poke-left`、`poke-right`、`tickle`、`drag`，游走叫 `swim`。
- `author`、`license`、`source` 必须如实填写，宠物页底部原样显示，见 §9。两只都是 DSH-TUI 的吉祥物，作者与授权见仓库根目录的 `ASSETS.md`。

### 3.3 运行时加载

- App 内同一时间只解码当前这一段，加上常驻的 `states.idle[0]`；其余按需解码，用 LRU 缓存最多 2 段。Deepy 全部解码约 139 MB，不能整包预解码。
- 悬浮窗在 Kotlin 侧按显示尺寸降采样解码，比如 Deepy 降到每逻辑像素 2 个像素，最大一段从 12.9 MB 降到约 2.1 MB。
- Flutter 端和 Kotlin 端读的是同一份 `app/assets/pets/<id>/`，Kotlin 从 APK 的 `flutter_assets` 里读。

### 3.5 Codex Pet 导入映射（C901）

Codex Pet zip 复用 `PetLibrary.install`，无 `pack.json` 时才识别唯一顶层或一层文件夹中的 `pet.json`。无版本号按 v1；v1 图集 1536×1872，默认 8 列 × 9 行，每格 192×208；v2 图集 1536×2288，固定 8 列 × 11 行。读取本地 PNG 或静态 WebP；WebP 转成 PNG，保持原像素网格。转换结果按下表生成 schema 1，`pixelArt: false`、`scale: 1`，再走与普通包相同的完整校验。

| 我们的状态或反应 | Codex 行 |
|---|---|
| idle | idle |
| thinking | waiting |
| working（所有档位） | running |
| juggling | running |
| notification | waiting |
| attention | review |
| error | failed |
| sweeping、carrying | running |
| sleeping | idle（停在首帧） |
| waking | jumping |
| roam | running-right；当前运行时向左镜像同一轨道，未选择独立 running-left |
| tapLeft、tapRight | waving |
| tickle | jumping |
| drag | running-right；当前运行时没有按拖动方向切轨道的入口 |

转换保留 Codex 默认逐帧时长和轨道别名。v1 可覆盖动画、帧网格及受限 fps，但图集尺寸必须精确匹配；v2 自定义网格/动画拒绝。v2 多出的 look 行不绑定；sleeping 使用 idle 首帧，DSH 持续态循环，和 Codex 非 idle 播三轮后回 idle 有差别。每个这些损失都写进 `codexImport.warnings`，来源图摘要写进 `codexImport.sourceSha256`，供主线导入结果页展示；没有上传或联网取图。作者、授权、来源按原字段保留，缺失仅作提示，不推断可公开发布。

Clawd 主题 zip 的导入走宠物包转换工具（`app/tool/make_pet_pack.py`），在手机端运行之前要先确定 APNG 和 GIF 怎么解码。

### 3.6 导入自己的宠物包（已做）

宠物设置的选择器最后一格是「导入」，收 schema 1 或上述 Codex Pet zip。实现在 `app/lib/pets/pet_library.dart`。

- **zip 结构**：`pack.json` 放在 zip 顶层，或一层文件夹中，候选必须唯一；有 Schema-1 清单时以它为准，坏包不回退到同时出现的 Codex 清单。拒绝路径穿越、重复文件名和 Unicode 15 NFC/full-casefold 别名冲突、加密、链接/非普通文件和重叠的 ZIP 条目；不按归档路径直接解压。仅保留清单和它引用的图。归档压缩及声明展开量各不超过 64 MiB、最多 256 条目，实际成员解压也受配额约束。
- **检查**：
  - JSON 严格 UTF-8，拒绝转义后重复键、孤立代理码点、非有限数和过深嵌套；再过 `PetPack.parse`，和内置宠物用同一套解析。
  - 再过悬浮窗那套更严的解析（`PetPack.kt`）：`scale`、`canvas`、帧格宽高、`cols`、每帧的 `i` 和 `ms` 必须是整数；`frames` 里不能有缺字段的项（App 会跳过，悬浮窗会整包拒绝）；`frameW`、`frameH` 必须正好等于 Kotlin Float32 算法下 `box × scale` 的截断值。沿用 c76c0db2 的限值：scale/帧格/cols 最多 4096，canvas 及帧 i/ms 最多 2³⁰。
  - 序列帧图必须是平铺在同一层的 PNG 文件名，不能有路径，不能以 `.` 开头。
  - 每张图每边不超过 4096 像素，解码后不超过 16 MB，压缩后不超过 8 MB。
  - PNG 要完整读一遍：合法且有序的 IHDR/PLTE/tRNS，所有 CRC、连续 IDAT、精确 zlib EOF/Adler32、Adam7 或普通扫描行长度及过滤值都要通过；拒绝 APNG、未知关键块、尾随数据。附属压缩元数据有独立解压预算。最后用实际像素解码器校验绘制所需块，仍保留原验证后的 PNG 字节。截断/损坏图不会替换已有宠物。
  - 每段动画的每一帧都必须落在图内。
  - 整包最多 64 张图，合计不超过 48 MB。
- **存放**：装到 `<应用支持目录>/pets/user-<id>/`，并把 pack.json 里的 `id` 改写成这个值；`scale` 和 `pixelArt` 按 App 的读法写明（悬浮窗要求有 `scale`，缺 `pixelArt` 时两边默认值相反）。在 Android 上这就是 `files/pets/<id>/`，悬浮窗（`PetSprites.kt` 的 `sourceFor`）在 APK 资源里找不到时就读这里，所以 App 内和悬浮窗看到的是同一只。
- **id**：pack.json 的 `id` 本身就是合法文件夹名（小写字母、数字、`-`，不超过 48 个字符）时原样保留，已带 `user-` 前缀的不再加；否则转成合法文件夹名，后面加原 id 的 SHA-256 前 8 位，所以「小猫」和「小狗」、`my cat` 和 `my-cat` 是两只。同一个 id 再导入还是同一只。
- **安装方式**：先写进 `.staging-*`，旧目录改名成 `.old-<时间>-<id>`，新目录改名进去，再删旧目录；id 相同就覆盖成新版。删旧目录失败不算导入失败。安装、删除、列出、读取一次只做一件。
- **中断恢复**：每次列出或读取前先收拾：有 `.old-*` 而正式目录不在，说明换到一半被杀，把旧的改回来；正式目录在，说明已经换好，删掉 `.old-*`。`.staging-*` 和 `.trash-*` 直接删。改回来时通知悬浮窗重读，免得它在宠物不在的那一刻读过、记成坏包。
- **加载**：`PetPack.dir` 指向这个目录，`PetSheets` 从文件解码。重新导入或删除时调用 `PetSheets.forget`，清掉旧的解码缓存，正在解码的旧图作废，不会再写回缓存；同时经 `reloadPack` 通知悬浮窗，它只按 id 和大小缓存，不通知就会一直显示旧图。
- **删除**：在选择器里长按导入的宠物。删掉的如果正是当前选中的那只，就换回默认宠物。删除先把这只的 `.old-*` 备份、再把目录本身改名成 `.trash-*` 移走（备份留着的话，下次收拾会把它当成换到一半的宠物恢复回来），失败时宠物完整留着、选中状态恢复，并提示「没能删除」。删除时临时换成默认宠物和失败后换回来都不算用户自己选，「藏起来 1 小时」保持不变；删除期间又选回这只的，删完换成默认宠物。悬浮窗收到 `reloadPack` 时，没在显示的这只也丢掉缓存，实时活动的宠物头像缓存一起作废。
- **作者与授权**：宠物页底部原样显示包里的 `author · license`（§9）。
- **共用入口**：Codex Pet 导入（§3.5）与市场下载都调用 `PetLibrary.install`。转换提示已保存在清单，主线负责结果页展示；缓存失效及 `reloadPack` 保持现有流程。市场规范化产物也必须通过当前 App 导入门，不能仅满足旧底层解析器的取整规则。

### 3.7 玩家自制包的兼容性约定

宠物包会跨 App 版本流传（市场下载、导出分享、旧手机），下面的约定保证旧版 App 不会因为新版格式整包拒绝：

- **未知字段被忽略。** 解析只读认识的字段，其余（作者注释、其他格式的键、将来的扩展）不影响加载，导出时会被丢掉；App 内和悬浮窗读同一份包，导入门的检查更严（整数、帧格尺寸等），但也不会因为多写的字段拒绝。
- **`reactions` 的跨版本格式是「基础名 + 编号」。** `"tickle": "a", "tickle2": "b", "tickle3": "c"`：旧版只播基础名、忽略编号键；当前 App 合并成列表随机抽。以后加候选只追加编号、基础名不动，旧版就还能跑。
- **数组不适合跨版本分享。** `"tickle": ["a", "b"]` 只在当前 App 内可读；导出到市场和市场规范化都会降级成编号写法。手写或工具生成的、要分享的包直接写编号形式。
- **编号只在基础名存在时合并。** 孤立出现的 `tickle2`（没有 `tickle`）保留为独立反应名，不被静默丢掉，误编号的包能看出问题。
- **缺省字段有确定回退。** 缺状态播 idle、缺 `tiers` 不分档、缺 `reactions` 键跳过该手势，见 §3.2 末尾；旧包不会因为少写字段被拒。

## 4. 状态归约 `PetMood`

`PetMood` 是 Dart 纯函数，只实现这一份，可单测。悬浮窗的 Kotlin 端只接收归约后的结果，不重复实现。

### 4.1 输入与范围

输入：所有主机上所有对话的运行快照，包括 `runActivityOf`、待确认事项、`AlertKind` 事件流、子代理数和压缩状态；另外还有当前在看的对话，以及最近一次触摸的时间。

**站在谁身上，就替谁说话：**

| 宠物在哪 | 基础状态取自 |
|---|---|
| 活动条上，表示当前对话在跑 | 当前对话（接管鲸尾，必须和活动条一致） |
| 输入框上，表示当前对话空闲 | 全局：所有对话按优先级取最高 |
| 悬浮窗 | 全局 |

档位永远按全局计数。气泡不受范围限制：任何对话的事件都可能冒气泡，规则见 §2.6。

### 4.2 信号到状态

| 宠物状态 | 我们的信号 | 类型 |
|---|---|---|
| idle | 范围内没有在跑的轮 | 持续 |
| thinking | `ActivityKind` 为 waiting、thinking，或者在重试 | 持续 |
| working | `ActivityKind` 为 tool、writing。按全局在跑的对话数分档：1、2、3 个及以上 | 持续 |
| juggling | 有子代理在跑。按子代理数分档：1、2 个及以上 | 持续 |
| sweeping | 正在压缩（compaction） | 持续，`autoReturn` 300 秒兜底 |
| notification | 有待确认或待回答的事（approval、question） | **持续，直到处理完** |
| attention | `AlertKind.done`，并且 1.5 秒内同一对话没有开始新的一轮 | 一次性 |
| error | `AlertKind.failed` | 一次性 |
| carrying | 导入宠物包：`UserPetsController.import()` 期间（导入失败也会复位） | 一次性 |
| sleeping | 空闲，并且 60 秒没有触摸 | 持续 |
| waking | 睡着时被触摸或来了事件 | 一次性，`wakeMs` |
| roam | 空闲期间随机触发 | 一次性 |

下面几种情况不改变状态：`ActivityKind.stopping` 保持原状态；`AlertKind.stopped` 安静地回到 idle，既不庆祝也不报错；压缩完成不庆祝；连接断开或引擎重启不进 error。

### 4.3 优先级与时长

- **优先级**照 Clawd：error 8 > notification 7 > sweeping 6 > attention 5 > carrying 4 = juggling 4 > working 3 > thinking 2 > idle 1 = roam 1 > sleeping 0。多个对话合并时取最高的；并列时取最近发生的那个。
- **一次性态**：至少显示 `minDisplay`，到 `autoReturn` 后回到当前的持续态。低优先级的新状态不能打断高优先级的一次性态。
- **完成去抖**：done 事件先压住，1.5 秒内同一对话有新一轮开始就丢掉，没有才升成 attention。这样目标续跑时不会每轮放一次彩纸。dsh-pet 和 Clawd 都单独处理了这种情况。
- **忙碌档**：升档立即生效，降档要等档位持续 5 秒低于当前档才降。thinking 和 working 之间互相切换时，各自至少显示 `minDisplay`，Deepy 是 1 秒。
- **互动反应**：在 idle、thinking、working、juggling、sleeping 之上临时播放，播完回到原状态；睡着时先播 waking。在 notification 状态下，单击改为「去看看」，见 §2.5。

### 4.4 输出

`PetMood` 的输出包括：

- `state`：状态枚举；
- `tier`：档位；
- `bubble?`：气泡，包含种类、标题、目标对话和合并数量；
- `target?`：最相关的对话，悬浮窗点击时用。

具体类型见 `app/lib/pets/pet_overlay_bridge.dart`。通道 `dsh/pet_overlay` 推送的内容是 `{state, tier, bubble?, target?, packId, size, quiet}`。

## 5. 渲染

- **像素画包**（`pixelArt: true` 且 `scale: 1`）：最近邻采样，`FilterQuality.none`，按 §2.10 的整数 `k` 绘制，左上角对齐物理像素。
- **高倍率包**（`scale > 1` 或 `pixelArt: false`）：用 `FilterQuality.medium`，`k` 不要求是整数，但锚点仍然对齐物理像素。
- **换动画时的过渡**（2026-11-20）：`pixelArt: false` 的包从上一段动画停住的那一帧淡入到新动画，用时 180ms（Dart 的 `petBlend`、Kotlin `PetView` 的 `BLEND_MS`），两张在同一图层里按 `旧 × (1 − t) + 新 × t` 叠加，身体中途不会变透明。像素画包照旧直接切，淡入会把硬边糊掉。换宠物、系统关了动画、暂停或只显示首帧时不淡入。需要更长的过渡（手从下沿伸上来、躺下去）时，在包里给该状态写一段 `bonus`，`chance: 1`，进入状态时先播它再接循环。
- 用 `CustomPainter` 或 `RawImage` 画当前帧，只在帧号变化时重绘，不要每个 vsync 都重绘；淡入的 180ms 里每帧重绘。
- 宠物所在的子树用 `RepaintBoundary` 隔开，宠物动起来时不能让聊天列表跟着重绘。
- 浅色和深色主题下都不给宠物描边、不调色。气泡用现有的玻璃表面令牌，跟随 App 字号。

## 6. 悬浮窗（Kotlin）技术规范

### 6.1 窗口

| 项 | 规定 |
|---|---|
| 类型 | 默认用 `TYPE_APPLICATION_OVERLAY`，需要 `SYSTEM_ALERT_WINDOW`。用户已为手机操控开了无障碍服务时，复用 `TYPE_ACCESSIBILITY_OVERLAY`，不需要额外授权 |
| 无障碍宿主 | API 30+ 从已连接服务派生独立 display/window context，由当前连接提供 overlay token。添加失败冷却 60 秒，服务实例变化可重新尝试；冷却期间仅在 `canDrawOverlays` 明确允许时回退应用悬浮窗。延迟移除仍未完成时等待轮询，不在下一帧回调中自旋 |
| 标志 | `FLAG_NOT_FOCUSABLE`、`FLAG_LAYOUT_NO_LIMITS`；**不加** `FLAG_NOT_TOUCHABLE` |
| 大小 | 平时窗口等于宠物 `hitBoxes.wide` 并上待机首段动画的帧格，再乘以 `k`，不是整个画布，更不铺满屏幕。命中框量的是身体，会漏掉待机图最下面一行（鲸娘的轮廓、Deepy 的阴影），所以要并上帧格。超出平时窗口的画面不裁，见「被拎起」「超出平时窗口的画面」两行 |
| 被拎起 | 拖动时宠物换成 `drag` 反应的姿势，身体整个被提起来：Deepy 的 `react-drag` 身体顶到 y 4.4，比宽命中框的上沿高 13.6 个美术像素，标准尺寸下约 52 物理像素，按平时的窗口会被截掉半个身子。所以按下开始拖时，窗口一次性长到「平时窗口 ∪ drag 帧格」，松手后换回平时的画面再缩回去；如果那一段的图要重新解码，等新画面出来再缩。长大和缩回都以平时窗口的左上角为原点，宠物在屏幕上不动。拖动中保证长大后的整个窗口留在屏幕和状态栏、导航栏之内；松手的吸附仍按手指带着平时窗口走到的位置计算，规则不变。实现见 `PetFrames.kt` |
| 超出平时窗口的画面 | 悬浮窗会播的任何一段动画（各状态的动画和分档、彩蛋、待机池、点按反应；游走除外，悬浮窗不游走），帧格超出平时窗口时，播放期间窗口临时长到「平时窗口 ∪ 该段帧格」，换成别的画面就缩回，原点同上，宠物不动。帧格本来就只裁到这段动画所有帧实际有像素的范围（§3.2 的 `box`；Deepy 是 5 倍图，取整到逻辑像素，最多多出不到 1 个美术像素），所以长出去的就是这段画面本身。取并集，只朝超出的方向长：Deepy 的 typing 只向左长 8 个美术像素、向上长 1 个，thinking 的思考云向上 12、向左 8，conducting 向上 18、向左 7；鲸娘的 thinking 向上 11、向右 3，conducting 向上 11、向左 10、向右 4。2026-11-01 之前只有 attention、waking、working 三个状态的首段这样做，其余的按平时窗口截掉，标准尺寸、dpr 2.75 下：Deepy 的 thinking 上方截掉 45 物理像素、左边 31，music（1 个子代理）上 32、左 24，conducting（2 个以上）上 72、左 28；鲸娘的 thinking 上 22、右 6，conducting 上 22、左 20、右 8。吸附时按「平时窗口 ∪ 所有长大的窗口」留位置，长大的窗口在任何吸附位置都在屏幕内，不压状态栏和导航栏。代价一：贴边留的位置更多，Deepy 贴左离边多约 8 个美术像素、贴顶低约 18 个（原来 14 个）；鲸娘贴左多 10 个、贴右多 4 个、贴顶低 11 个（原来 5、0、8）。代价二：长出去的透明部分在播放期间一样挡住下面 App 的点击；thinking、juggling、notification、sleeping 都可能持续很久，所以只长这段画面需要的方向和范围，不按所有动画的最大包围盒长。实现见 `PetFrames.kt`，每个内置包每段动画每一帧的不透明像素都由 `PetFramesTest` 解码 PNG 核对 |
| 命中 | 触摸只认身体：平时窗口，并上当前动画的命中框（§3.2 的 `hitBoxes`，与聊天页 `hitBoxFor` 同一规则：`byAnim` → `sleepingAnims` → `wideAnims` → `default`）。长大的窗口里其余部分（思考云、Zzz、音符、跳起时高出平时窗口的那一截）只画不认，从那里开始的触摸什么都不做：这一下本来就到不了下面的 App（窗口收走了），本意多半是点下面的按钮，不应该变成打开对话。Deepy typing 的电脑在它的 `byAnim` 框里，照常能点能拖；happy、waking 高出平时窗口的那一截，和聊天页一样不算命中（聊天页也按这段动画的命中框，不跟着跳）。实现见 `PetFrames.hit` |
| 移动 | 窗口位置只由我们自己动：拖动时每个触摸事件都按手指直接算出位置，松手吸附用自己的动画。窗口的大小和位置在同一次布局里一起变时（拎起长大、松手缩回、三段动画长大），系统默认会放约 0.4 秒的移动动画，其间不理后面的位置更新：拎起后宠物最多落后手指 220 像素、440 ms，再一下跳过去。所以每个悬浮窗都关掉它：API 34 起 `setCanPlayMoveAnimation(false)`，更早的系统设同一个私有标志 `PRIVATE_FLAG_NO_MOVE_ANIMATION` |
| 穿透 | 不做像素级穿透。Android 12 起，带 `FLAG_NOT_TOUCHABLE` 的不可信悬浮窗，如果窗口 alpha 高于 `InputManager.getMaximumObscuringOpacityForTouch()`（默认 0.8），系统会拦掉落在它下面的触摸，宠物又不能做成半透明。所以窗口要做小，窗口内的触摸都由我们自己处理。也因为这一条，不能一开始就按所有姿势的最大包围盒把窗口开大：透明的部分一样会挡住下面 App 的点击，限制可触摸区域或拆成两层窗口都绕不开（判定看的是窗口框，不是可触摸区域）。只在拖动时（手指本来就按在宠物上）和「超出平时窗口的画面」播放时临时长大，而且只朝需要的方向长。另开一个不可触摸的窗口专画溢出部分也查过（2026-11-01）：无障碍宿主的 `TYPE_ACCESSIBILITY_OVERLAY` 是可信窗口，不受这条限制；但 `TYPE_APPLICATION_OVERLAY` 要让触摸穿过，那个窗口的 alpha 只能到 0.8，跨过平时窗口边缘的思考云、道具会在边上出现一道明暗接缝，而且两个窗口要在拖动和吸附滑动时逐帧同步移动。所以没有采用 |
| 气泡 | 单独开一个小窗，可以点，收起即移除 |
| 动画 | 用 `Choreographer` 驱动，但只在帧号变化时 `invalidate` |

### 6.2 省电

- 灭屏、空闲变淡、App 回到前台时，完全停止绘制（变淡本身的 0.4 秒淡出除外）。
- 待机时不靠降帧来省电，因为降帧会让动作发卡。做法是停在静帧，每隔 8 到 15 秒完整播一次待机小动作。
- 有事件时按原速播放。
- 5 分钟无事自动收起，见 §2.7。

### 6.3 进程与前台服务

- Flutter 引擎被缓存，不随 Activity 销毁（`MainActivity.shouldDestroyEngineWithHost = false`）。所以只要进程还在，`PetMood` 就在跑。
- 本机引擎在跑时，悬浮窗挂在 `DshService` 上。只连远程主机时，用悬浮窗自己的前台服务，类型是 `specialUse`（manifest 里已经声明了 `FOREGROUND_SERVICE_SPECIAL_USE`）。
- 当前 `targetSdk` 是 28。Android 15 对「凭 SAW 在后台启动前台服务」的收紧按 target 生效，眼下不受影响，但将来提高 target 时必须先保证悬浮窗可见。在 `docs/architecture.md` 的 target 升级清单里记一笔。

### 6.4 权限引导

1. 用户打开「App 外显示」时：如果无障碍服务已开，直接用无障碍悬浮窗，不再申请权限；否则跳转 `ACTION_MANAGE_OVERLAY_PERMISSION`。
2. 从浏览器或文件管理器侧载安装、并且是 Android 13 及以上的机器：悬浮窗属于「受限设置」，Android 15 CDD 明确列入。按受限设置的引导，先打开应用信息页，允许受限制的设置。
3. vivo 和 OriginOS 另有自己的悬浮窗开关，默认关闭。`ACTION_MANAGE_OVERLAY_PERMISSION` 在部分机型上只跳到总列表，入口位置要真机核实。旧版系统上 `canDrawOverlays()` 不可靠，判断是否授权以 `addView` 成功为准。没开就停在引导页，不报错。
4. 被拒绝时开关退回关闭，宠物页那一行显示「未授权」，点它重新引导。
5. vivo 和小米另有「后台弹出界面」权限。单击悬浮窗去拉起 Activity 时可能被拦，被拦就退回发一条可点的通知，做法照 `SystemActions.kt:263-268`。

## 11. 验收

- **归约器**单测要覆盖：
  - §4.2 的每一行；
  - 优先级合并；
  - 完成去抖（续跑轮不庆祝）；
  - 升档立即、降档延迟 5 秒；
  - 一次性态的最短显示和自动回落；
  - notification 持续到处理完；
  - stopped 不庆祝；
  - 站位范围：在活动条上看当前对话，在输入框上看全局。
- **站位几何测试**：
  - 脚线和胶囊上沿的误差不超过 0.5 逻辑像素，键盘升起的动画中每一帧都要满足；
  - 拖动后吸附正确；
  - 拖进禁区会被推出；
  - 命中框外的点按能到达输入框、按钮和列表；
  - 弹出层打开时宠物不吃触摸。
- **清晰度**：在 devicePixelRatio 为 2.0、2.625、2.75、3.0、3.5 下截图并放大，每个美术像素都是等宽的整数个物理像素，边缘不糊。
- **提醒**：
  - 前台在聊天页、宠物可见时，别的对话做完只出宠物气泡，不出横幅；
  - 安静模式和宠物藏起来时，退回横幅；
  - 正在看的对话不冒气泡。
- **悬浮窗**：以下几种情况，在 Kotlin JVM 测试和模拟器里各走一遍：
  - 权限被拒；
  - 灭屏；
  - App 回到前台；
  - 进程只剩前台服务；
  - 被 `setHideOverlayWindows` 藏掉；
  - 空闲变淡；
  - 拖到「×」关闭；
  - 5 分钟自动收起；
  - 同一档位下，悬浮窗里宠物的身体高度与聊天页一致（两只宠物 × 小/标准/大 × dpr 2.0/2.625/2.75/3.0/3.5）；
  - 每个内置包、悬浮窗会播的每段动画、每一帧的不透明像素，都在它播放时的窗口里，也在吸附留出的范围里（JVM 测试解码 PNG 核对）；命中区不超出平时窗口和当前动画的命中框。
- **性能**：宠物待机时，聊天页不能因为宠物而每帧重绘；悬浮窗待机时，每分钟重绘的次数要和 §6.2 的节奏一致。
- **真机**：在 vivo 真机上验收。

## 14. 悬浮窗「问一句」、请求处理与语音（2026-10-30）

### 14.1 问一句和目标

长按菜单的首项打开单独的、仅在打开期间可获焦点的小输入窗。显示目标对话与主机，提供「新对话」切换；返回键、点窗外收起并保留草稿。IME 根据输入窗实际屏幕位置和局部重叠量抬升，重复 inset 不累计尚未布局的偏移；键盘消失后回到原停靠位置。

目标优先为宠物当前代表、位于当前主机、已知空闲且可用的对话；其他情况新建当前主机对话。宠物可能正在提示另一台仍连接的本机，此时不会悄悄切换全局主机。菜单中的「切换主机」供用户明确选择，SSH 仅列已固定主机指纹的主机，DSH Remote 仅列已信任的主机。

`askTarget` 创建 offer，绑定 host、connection、连接代次和 session；发送时重新验证。主机变化、重连、会话进入运行/审批/问题等待状态时拒绝发送并保留文本。新对话复用 `SessionsController.create`，再走 `ChatController.waitForSync/send`，保留正式聊天的历史、requestId 与同步语义。新建后发送失败的重试复用同一 session，不重复建空对话。

发送成功后由真实会话事件驱动 thinking/working；该轮完成的气泡显示经过掩码的回复开头（原生最多两行），点击打开完整对话。其他对话完成不泄漏正文；合并多个会话的气泡不显示单条回复。

原生输入草稿逐次保存到 App 私有 preferences。Flutter 未附着或没有 action handler 时，通过受保护的 `EntryActivity` 将文字交给前台新对话输入框，**不自动发送**。拉起失败时保留原生草稿；ROM 阻挡后台弹出时仍有现有通知入口。引擎未连接时输入窗明确提示，不直接拉起引擎或假装发送成功。

### 14.2 气泡审批和问题

批准只允许 `allowOnce` 与 `reject`，不提供「以后都允许」。原生按钮复用 `PromptInputPolicy`：出现后延迟启用、拒绝遮挡触摸和已知自动注入，保留 TalkBack 路径。Dart 使用通知的 `ChatAlertsController` 和原始 request，通过对应 host client 回答；host、root session、eventId、请求代次 token 必须全部吻合，撤回、重连或旧窗口上的按钮无法批准新请求。

只有完整、短小、没有秘密掩码和方向控制字符的工具名及 **全部 JSON 参数** 可批准；命令的 cwd、写入内容、替换文本不会只缩成文件路径。超过字符上限或实际气泡四行容纳不下时只能「去确认」。手机操控关键步骤继续使用已有 `PhonePrompt` 明确确认链路，不经桌宠简化审批。

单选问题只在一题、最多三个不重复的短选项、没有选项说明、详情或计划审查语义且题目完整可见时直接答。否则「去回答」进入聊天。选项换行显示，不截断后仍允许选择；自定义答案、多选与计划批准均留在聊天。

### 14.3 离线语音与前台降级

输入窗的麦克风按住录音、松开转写，滑出取消。录音沿用 `WavRecorder` 和 `MicArbiter`，音频只交给 **本机** 的 `sensevoice-local`、`host-local` provider；不会因为当前主机或语音默认选择变化而把音频交给远端或云 provider。模型未准备好时提示到 App 下载。

没有麦克风权限、录音启动被系统拒绝，或 Android 的 `AudioRecordingConfiguration.isClientSilenced` 表明后台录音被静音时，前台打开独立语音对话框。复用聊天的 `VoiceInputController`，强制本机离线 provider，不覆盖已有聊天草稿。识别完成或点击「返回桌宠」后把文本交回原生草稿，App 返回后台并重开输入条，仍须用户点击发送。

不新增权限或 microphone 前台服务类型：现有桌宠服务继续 `specialUse`，本机引擎服务声明不变。2026-10-31 在 API 35 x86_64 模拟器（App targetSdk 28）实测原生录音得到 47,660 字节 WAV，`configs=1 silenced=false`，桌宠前台服务类型为 `specialUse`；本地测试 Host 固定返回转写文本，验证了回填和用户确认发送，没有验证识别模型。API 34、OEM 后台政策和权限拒绝／静音后的前台降级仍未实测。验收必须记录：App 不可见时录音 service 类型、是否拿到音频/被 silenced、启动异常、前台权限授予、转写回填和返回桌宠；分别测试 API 34/35，勿把模拟器静音输入当作权限通过。

### 14.4 半轮盘与截图（2026-11-04）

App 外长按菜单改为朝屏幕内侧的半轮盘，左右停靠镜像。原始触摸流在长按后继续路由到轮盘，不要求重新按下；滑向选项连续高亮、轻微放大并向外凸出，松手执行。中心死区、外圈之外、系统取消、多指打断、窗口/代次失效时不执行。普通单击/拖拽不变；无障碍长按提供可点选按钮，极小屏/极大字体优先保证完整标签可达。展开与选中反馈使用短缓出/逐帧插值，跟随系统关闭动画设置，不按每次 move 重建动画。

2026-11-11 重画（`PetMenuView.kt`、`PetWheelGeometry.kt`）：

- **形状**：方块按钮换成 52dp 的圆形图标，每个按钮占 62dp 弧长，半径 112–138dp（原 172–220dp），拇指从宠物身上够得到。名字画在按钮外侧同一条射线上，手指盖住图标时仍看得见；中间的提示框去掉。
- **底**：整圈画在一层跟主题走的柔光上（浅色 `#EDF1FA`、深色 `#12151B`，宠物身上留空，标签之外淡出），盖在任何应用上都读得清。窗口因此比按钮大一圈，圈内的触摸归轮盘。
- **手感**：按钮的大小跟着手指的角度连续变化，并把两侧的按钮沿弧线挤开，不再一格一格跳；选中项和触感反馈仍按扇区离散判定，带原来的角度迟滞。出场从中间向两头绽开，用带少量回弹的弹簧；收起反向。执行时那一颗留在原地放大淡出，外加一圈向外的描边。全部由同一个逐帧循环推进，关闭动画时直接到位。
- **原地松手保留**：长按后没有滑动就松手，轮盘留着（以前只有列表降级这样）。之后的触摸由轮盘窗口自己处理：点按钮执行，可以按住再滑到别的按钮，点别处收起。8 秒无操作自动收起照旧。
- **取消区**：离宠物中心不到半径一半（至少 52dp）的范围内不选中任何项。
「截图并问 DSH-Go」是用户主动操作，不经过 AI 手机操控工具：Android 11+ 已连接无障碍服务时，先隐藏宠物、轮盘及手机操控浮层，截取当前主屏，再自动返回 App。截图期间禁止状态刷新重新显示宠物；失败或操作失效后恢复浮层并清理私有缓存。安全窗口、缺少无障碍或系统不支持时显示稳定的本地化错误，不绕过权限和截图保护。

截图经私有临时目录与受保护的 `EntryActivity` / `ShortcutsPlugin` 进入 Flutter，消息为 `{kind: screenshot, path}`；原生同时验证进程 token 与缓存路径，不能用外部 Intent 附加任意私有文件。`SystemEntryHost` 复用 `ComposeRequest.fromShare` 校验、读取并删除临时副本，回到新对话输入区。旧对话草稿不动，新对话已有文字与附件按原预算合并；原生回填不创建模型请求、不自动发送或上传图片；网页模式沿用已有分享附件通路，也不提交提问。后台拉起被 ROM 阻挡时沿用通知入口。
