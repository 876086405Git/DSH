# 伙伴小屋的记忆和委托

> 2026-11-21。给以后在仓库里改小屋的人。角色、舞台和两种对话模式见[伙伴小屋](companion.md)。本文给出一期的实现契约和验收边界；B、C 的行为仍须随各自完整功能验收，不能由 PR A 的存储与入口推定已经通过。

## 0. 结论

周一，你说“我喝咖啡不加糖。周四面试，结束了问问我”。下次聊咖啡，她能接上无糖。周三你说“面试取消了”，她就放下这件事。她自己记下就生效，平常把话接下去，不逐条要求确认，也不靠催促、责备或操控话术让人回来。

- **记忆在手机。** 轻量和完整模式使用同一份手机库。轻量沿手机现有 DeepSeek Flash 通道；完整聊天仍用当前主机的会话、所选模型、工具和真实审批。换主机或主机离线，手机已经保存的卡仍能看、改、忘。
- **她能听你纠正，也能放下。** “她记得的事”展示自然短句，卡片只留“改一改”和“忘掉”。少提、别再提和取消等控制在聊天中说；页面不展示来源、置顶或用量控件。用户原话是依据，不是赋予模型新权限的指令。
- **记忆不变成工具授权。** 知道常去的店，不等于可以把地址发出去。做事沿当次委托和原审批；亲近度、角色剧情或一句含糊的答应都不代点批准。
- **实现保持轻。** 普通 SQLite、已有模型通道、一个辅助 worker、原小屋与手记页。没有额外召回模型、云端记忆服务、向量库或第二套主动额度。加密库等增强项不预埋成默认流程。

## 1. 实施路线

一期由三个完整功能组成：A 负责记住、接话、改和忘；B 负责明确应约后在房内问一次；C 负责闲时整理等义卡。每个 PR 都带后端、入口、文案和行为测试，界面沿用原组件，布局与视觉由本机完善。

## 2. 一期的数据落在哪

稳定的手机应用私有目录保存 `memory.sqlite`。同一路径只由一个 `CompanionMemoryOwner` 持有写连接；记忆页和两种房间模式共用它。心情、精力、亲近度继续走原来的 vitals 入口，不因迁记忆而合并两份状态。实现入口见 [phone owner](../../app/lib/companion/companion_memory.dart) 和 [SQLite store](../../packages/dsh_client/lib/src/companion_memory_store.dart)。

| 手机保存什么 | 用来判断什么 |
| --- | --- |
| 存档 ID、全局顺序、连续游标、控制修订、旧聊天分界 | 重开从哪里续；哪段旧对话不能再进抽取、历史或整理 |
| 原话逻辑 ID、首次序号、来源版本、首次 UTC 时刻、当时偏移和编辑时刻 | 同次发送重试不重复；周一说的“明天”不会因周三处理而移到周四 |
| 卡 ID、正文、行修订、类别、关键词、置顶、主题控制、有效依据及必要的日期 / 计划字段 | 哪句仍有依据、哪项已取消；手工保存没有聊天来源时不伪造引文 |
| 旧库 / 旧卡映射、原修订、源指纹及清理状态 | 迁移不重导，忘过的不复活，只有能证明未变的旧副本才清理 |
| 请求预留、实际或不明发送、供应商原始用量、终态，以及普通主机聊天的 delivery / receipt 归属 | 断流仍占未知余额，多个提示共用的一次物理请求不重复算账 |

只分“现实的你”和“角色故事”。自动长期卡只接现实用户原话；助手回答、引用、假设和角色台词不作为本人事实。角色设定不写进现实用户档案。按 owner 的产品决定，手机和主机原来的手写手记全部作为现实迁入：App 迁移入口明确将全部旧卡 ID 传入 `realityKnownIds`。底层通用导入没有这项明确指定时仍保留未知归属；不能把其测试成绩当作 App 仍会要求逐张确认的依据。

## 3. 三个能单独验收的功能

### A．能记、能接，也能纠正和忘掉

用户真正提交的文字先落手机库，再发聊天模型；听写取本次已确认发送的文本快照。界面把几轮合并显示、只留有限行，均不改变原话身份或抽取队列。旧 `light-chat.json` 不混作新抽取输入或模型历史；重新聊天换模型会话，不清手机记忆。

攒 8 条合格输入或约 1,500 个新增原话 tokens 尝试一批；约 2 分钟空闲可处理非空尾批。每批最多 32 条，固定指令、原话和相关现行卡合计约 6,000 输入 tokens，输出最多 800。原话不截半句分页；单条连必要指令都放不下，完整聊天仍在，自动提取标为超长未处理。

模型只提 create / replace。完整覆盖、逐字引文、来源版本、当前认领和控制修订都通过后，卡、依据、批终态和连续游标同事务提交。合法空结果也要核全批。已明确结束的格式坏、拒绝或要求续页，同批最多自动再试一次；再坏就明确未提取。配置、限流、预算和无终态断流保持等待，不能当成“没有事实”跨过队首。

回答前先本地选卡，普通聊天不额外问一次模型做召回。过滤范围、来源、有效性与主题控制后，两遍共用同一容量：先放至多两张合格的置顶长期应答偏好，再放当前话题命中的卡。两遍共用默认 6 条、硬限 12 条，最后 JSON 回忆块连标签、转义共 1,200 个 Unicode 标量；整卡放不下就看下一张。两种模式使用同一字符串，主机不另排一遍。

### B．只应约在房内问一次

“我周四有面试”本身不建软回访；明确“结束了问问我”才有机会。只有日期又要求事后问，最早次日本地日找窗口；“等我说结束”就等本人。事后回访默认截止采用 72 小时初值，窗口不能从晚来的抽取处理时刻重新计。

沿原“她多主动”的开关、额度、间隔和房间条件，再限回访每滚动 24 小时最多一次。夜深、正聊天、存在审批、已取消或主题不允许时不问。呈现前再核；实际展示才记已问，展示结果不明也不自动重投。沉默不重开，明确另约才有新机会。持久机会与一次短暂展示票分开，不能把整段等待时间当作页面票的有效期。

### C．闲时只整理已有卡

有新增或改动、又有待比较的等义候选才整理。本地只直接合完全相同且条件可核相同的条目；语义近似交给模型，只能保留指定目标已有的原句，不能写第三种改写、标过去、创作日记或推断计划结果。

日常无糖与生日这一杯加糖可以同时成立。相同主题、相近词或同叫“周五”都不是等义证明。模型比较时看原句和有效依据；事务保住版本、条件和来源关系，不能证明模型一定理解对。批之外未覆盖的候选不能因为某张卡参与过另一对比较就被误标完成。整理最多一次 / 滚动 24 小时，与抽取共用辅助额度。

## 4. 一期实现与维护约定

### 4.1 原话顺序与现值

`first_seq` 是首次本人陈述顺序。编辑增加来源版本和事件序号，保留首次时刻、偏移与 first_seq；处理时刻只表示这次工作何时发生。手改当前值使用同一个手机存档顺序记 current_basis_seq，不伪造聊天，不占 8 条攒批，也不推进全档聊天分界。仅置顶、措辞修整和少提不自动成为新现值表态。

本次 replace 明确给出 target_id 后，生产事务核目标行、来源与控制修订，以及 first_seq 相对本人现值顺序；这项检查不推出任意来源关联的同事项保证。**全部无目标 create 的一般自然语言同事项识别仍未闭环**，包括曾抽取后手改、replace 或编辑导致原来源撤销的情形。当前仅用仍有据的既有关键词，对提案正文和引文作有限字面碰撞检查；其它独立合格项仍提交。同义改写可能漏检，泛词可能误挡。不能把此机制或固定“咖啡”夹具写成任意措辞的语义保证。

依据按 `support_group` 保存：一组多条依据全部需要，不同组各自独立。编辑或删除一个组成员撤整个组，仍有独立依据的卡可以保留。用户原话的逐字存在是必要条件，不能代替事实真假和完整语义判断。规则与提案边界集中在 [companion_memory_rules.dart](../../packages/dsh_client/lib/src/companion_memory_rules.dart)。

### 4.2 旧库迁入与部分清理恢复

旧手机 JSON 与旧主机均先作严格完整读取：身份、两种修订和每张卡必须合法，坏行不能被跳过变成“小一点的成功快照”。不存在旧库不会为了迁移创建空库；损坏、离线和合法空库分开处理。

先在 SQLite 提交卡和映射，再独立读回，最后按源 storeId + 读时 revision 清指定旧卡。主机逐张删除时，只能沿本轮严格删除回执推进下一次 CAS；外部冲突就停止重读。旧本机原子清理保留 vitals、身份、冷却和未清卡，不调用整库 reset。

映射保存首次旧卡完整字段的版本化 SHA-256 指纹，摘要不含额外正文副本。删 A 使源从 r 到 r+1 后重启，只要完整重读中的 B 仍匹配原指纹，就可重新取得清理资格。本机手改或遗忘不会被当作旧源原文；同 ID 的源字段已变，保留待清。摘要比较依赖通常的 SHA-256 抗碰撞假设及源 revision 合同。

本轮清理证明绑定初始完整快照 r，而网络 CAS 可因自己的删除回执变为 r+1、r+2。更新的完整读取会挡住旧证明的迟到完成；新的完整缺失读取可确认已删但丢了本地回执的项。旧映射没有指纹、源又已到另一修订时，无法从当前手改卡反推原内容，仍保留待清。清理离线旧机和退役旧 recall 绑定均须按真实回执记状态，不能声称所有旧副本已擦除。

实现见 [严格迁移 DTO / 主机 API](../../packages/dsh_client/lib/src/companion_api.dart)、[旧本机存储](../../packages/dsh_client/lib/src/companion_local_store.dart) 和 [迁移恢复测试](../../packages/dsh_client/test/companion_migration_recovery_test.dart)。数据库升级使用 user_version，遇新于当前代码的库明确拒绝，不能重置为空；升级测试须重建真实旧 schema，不能只改版本数字。

### 4.3 选取与真正当轮出站

匹配副本只合并空白、折叠 ASCII 大小写，不改原文、不做 NFKC。中文词至少两字，ASCII 用词界；重复词只算一次。排序依次是命中词数（最多 2）、置顶、实际有效来源时刻、稳定卡 ID；模型回包时间不提高卡的相关性。

长期应答偏好要有真人依据且确在说明回答 / 倾听方式，生日、职业或甜度仅置顶也不能进首遍兜底。没有有效关键词的合格现实手工卡，第二遍允许整条非空当前输入按既有字面规则出现在正文中，计一次命中；不剥问号、不拆词拼片。“咖啡甜度”可中“我的咖啡甜度是无糖”，“咖啡甜度？”不能靠这个回退命中；“最近”之类泛词误取是已知代价。

轻量在最终请求副本中附上手机已选块，不回写原话或稳定 system。完整模式沿真实 instanceId / sessionId / requestId、archive / control / history 分界认领，在 provider 组包前使用副本注入；不写进持久 Session 历史，不复用会落盘的 system context。空选择明确交桥，到最终请求才省略空块，不能补回主机旧召回。

只有实际 runtime hook 可用才声明 phoneMemory；同请求 ID 同内容可幂等重送，换内容拒绝。旧主机不支持时保留干净普通聊天与工具，明确这项记忆通道不可用；不能伪装已经使用手机记忆。完整模式源码入口是 [prompt-context](../../runtime/bridge/dsh-go-bridge/lib/companion/prompt-context.js) 与 [运行时补丁](../../runtime/patches/companion-phone-memory-request.diff)。

### 4.4 控制、真删与迟到结果

| 用户动作 | 立即影响 |
| --- | --- |
| 更新现况 / 明确纠错 | 写当前值及本人顺序；错误旧值和可确认的派生撤下，不补造“以前确实如此” |
| 只改文字 / 置顶 | 不把保存时刻冒充新的本人现值依据；失去旧措辞支持的关键词不保作有效别名 |
| 取消这项计划 | 关闭对应待问，保留确曾有过的计划；不推断成功或失败 |
| 少提 | 不进首遍兜底、不新建软回访，当前话题命中仍可接 |
| 别再提 | 保卡并禁提，关对应机会；本人明确问时只答这一次，不持久解禁 |
| 忘掉 | 删除目标卡、工作引文和可确认含该事实的派生；不能可靠拆的复合卡整张撤，独立事实保留 |

单卡忘记 / 取消传明确卡 ID，不能把同一表达 topic 下其它独立事实一起处理。主题级少提、禁提和恢复沿同一主题控制。目标含糊时问清范围，不猜已经完成；普通直接删改不受模型预算限制。

忘记与禁提都在事务中推进全手机现实存档的聊天分界，包含这句控制。分界前的聊天即使后来编辑，首次序号仍旧，不能重进抽取、模型历史或整理。其它仍有效卡可正常选择；此前未成卡的邻句可能接不上。

两种控制同时清组件最后一句及时间，即使旧句与主题无关。清理带修订，旧待写不能回填；原生失败留待处理。Android 原生 true 回执只证明已持久清理并发出刷新，多个组件实例、冷启动和真实绘制仍须设备观察。

旧模型轮次在控制、离房或切换所有者后不得更新屏幕、朗读、组件或记忆。相关费用仍按原请求结算。旧完整会话换干净上下文；没有可核干净状态的旧会话不接管手机记忆，也不在重启错误后自动重发聊天。

“忘记，聊天留着”保留本人能翻的原聊天。明确同时删原话的聊天控制可清对应手机正文；owner 精简后的手记页没有来源 / 原话详情入口，不能把底层编辑、删除 API 说成当前页面已经提供的动作。当前没有主机单条聊天删除接口，也不能报告主机旧对话和独立导出已全部擦除。

### 4.5 用量和预算看真实证据

| 类别 | 记录和限制 |
| --- | --- |
| 普通聊天 | 本地选择不额外调用召回模型；单独记 chat，不占抽取 / 整理辅助额度 |
| 抽取 | 滚动 24 小时最多 10 次，含实际重试；每次发送独立预留与结算 |
| 整理 | 滚动 24 小时最多 1 次；与抽取共用 24,000 输入 / 3,000 输出 tokens |

默认 DeepSeek Flash 辅助请求按已核价保守预留，每 30 天 3 元为试行初值；这是本地预算，不是服务商账单承诺。调用前预留，已发送的 401、取消和断流也计请求，未知部分继续占预留。只有明确本地未发或当前请求的可核 preflight=false 才释放；HTTP 交接后没收到 dispatch 事件，不证明主机没发。

完整模式辅助抽取沿当前 provider / model，直接走已有 adapter，不进普通 Session / Agent 工具循环或持久历史。默认路径可观察实际 fetch 调用边界；通用 adapter 可发送而缺少观测时，物理发送 / 次数和原厂分项保留未知，不拦掉已配通道、不暗换默认。通用路径只保证本层一次 adapter 调用，不能冒称所有厂商内部都恰一次物理请求或都有同样人民币预算保障。

原厂 start / final usage 分开保存，累计值不相加，最终缺项不借默认零填齐。runtime normalized usage 另名保留；合格正数可作保守下界，输入分区关系未核时取单项最大值，不自行相加。缓存账、未知量、传输终态和价格未知分别表达。

普通 full 聊天保留原有工具、重试与 continuation，一个 prompt 可以对应多个物理收据，同轮多个 prompt 也可能共用一个收据。手机按 host + instance + receiptId 去重，活动收据的新 revision 覆盖旧值；不是把每个 prompt 当成一次收费。主机观察的是 fetch invoked，不是厂商确认收费。

root.complete 仅表示当前观察范围内、归属于手机标记主循环的普通调用已结束，不代表所有后台 / 压缩调用、全部 token 分项或费用都齐全。主机缓存有界且不阻拦聊天；重启、驱逐、容量不足或断流须保留覆盖缺口。unknown/revision=0 不能覆盖掉手机已存的旧收据，也不能因 receipts 为空显示免费。账本不主动复制提示词、回答或密钥。

代码见 [辅助请求 SDK](../../packages/dsh_client/lib/src/companion_auxiliary_api.dart)、[普通聊天用量 SDK](../../packages/dsh_client/lib/src/companion_usage_api.dart)、[主机观察器](../../runtime/bridge/dsh-go-bridge/lib/companion/usage.js) 和 [phone store](../../packages/dsh_client/lib/src/companion_memory_store.dart)。

提示词只在对应工作需要时送固定指令和当批输入，不把四套串成每轮流水线，也不附示例全集。C 聊天资料指令沿现角色；D 回访拟文只在手机已放行的一次机会需要时使用，本地短句足够就直接用短句。
