# 匿名使用统计设计

先解决输出 Token 无法对账的问题，再用同一套日包回答哪些功能有人用、在哪里失败、用了以后是否回来。沿用现有匿名统计开关和 UTC+8 日账本，不加实时心跳。

## 日活、留存和机型

[现有日账本](../../app/lib/usage/usage_ledger.dart) 在开关开启后记账，最近七天内可补发结束日。[Worker](../../services/share-worker/src/usage.ts) 接收 v1–v3；v2 起可以带机型和 ROM，v3 加了 Token 与酒馆、伙伴、通话计数。设备信息取不到时可以降为 v1。旧记录里缺失、未覆盖和真实零无法完整区分；保留旧报表和名称，按新口径计算时不把旧数据补成零。

| 指标 | 新口径 |
| --- | --- |
| DAU | UTC+8 当天至少一次前台的去重匿名安装数；开关关闭的安装也计入，关闭态只发 base 行。后台任务、下载请求、更新检查与上传发生日都不能代替前台日。 |
| D1 / D7 | 本统计周期首个前台日为 D0（关闭统计不重置，日活与匿名 ID 连续）；分子为同一身份在 D0+1 / D0+7 恰好那一天再次前台的安装数，分母为对应观察日已成熟的 D0 cohort。升级用户也会进入，报表标「统计启用 cohort」，不写「新装留存」。 |
| 机型和 ROM | 分别报告有效字段覆盖率，分母是同日、同平台的新口径前台安装数（含仅日活的安装日，报表单列）；缺失进 `unknown`；机型热榜只出单维 Top N，小于 20 个前台安装的组合并为「其他」，不与 ROM 等做细粒度交叉。 |
| 实时在线 | 日包只能说明那天有过前台。报表不把当前收到的日包当在线人数。 |

最近日期显示「暂估」和截至时间；过完目标日的七天补发窗口才进入成熟趋势和留存。功能统计关闭再开启重新开始；日活与匿名 ID 连续，D0 不重置。90 天 ID 轮换不生成新的 D0 标记。首次 v4 ID 从该周期开始才生成，避免常规轮换打断 D1/D7。客户端日期用 UTC+8；耗时用单调时钟。

## P0：Token 对账规格

[主聊天现在只在新到的助手消息事件上计量](../../app/lib/state/chat_state.dart)，旧日表没法指出输出偏低是上游不报、App 没看到最终事件、解析丢字段还是采集覆盖不足。[客户端解析](../../packages/dsh_client/lib/src/models.dart) 已经可见 usage 帧，但归一化对象可能把缺失变成零。保留字段是否存在，后续再归一化值。

1. **一次实际模型调用是计量单位。** 本机主聊天优先由能够观察调用终态的引擎/桥接提供结果，计量不依赖 UI 收到最终消息。远程主机按经验证的用量能力归类：可以看到发起和中途帧，就记可观测调用及部分用量；拿不到调用级数据就标覆盖不足。酒馆和伙伴从实际发请求的适配器结算，覆盖能观察到的辅助调用；[酒馆的轮次结束事件](../../packages/dsh_tavern/lib/src/api.dart) 只作定位线索，不和调用级数据重算。ASR/TTS 不进文本 Token；通话触发的 LLM 调用由实际适配器归属一次。
2. **一个调用只结算一次。** 本地按来源与调用键折叠重播、重连和重复终态。适配器声明用量帧是累计快照还是增量，以及怎样识别最终值；实际向服务端另发一次请求才算另一次调用。同一用户轮次可以触发多个调用。一次取消若仍有可核验的最终 usage，就照常结算。连续启动后没终态的调用由超时或重启退回 `abandoned`，不补估算值。
3. **输入、输出分别分类。** 可观测的已结算调用各按 `final_positive`、`final_zero`、`partial`、`missing`、`invalid` 五种互斥状态入桶；只有最终字段明确为 `0` 才进 `final_zero`。负数、非整数或超过安全整数范围进 `invalid`。中途快照只进入「部分观察量」。普通输入、缓存读/写只有提供方契约证明互斥可加时才拆算总输入；[已有 DSH 样本](../../packages/dsh_client/test/fixtures/follow_approval_with_resync.jsonl) 的 `10129 + 2 = 10131` 可以作为该解析路径的对账基准。推理 Token 若定义明确作为输出细分，不另加到输出总量。统计不按字符串长度补 Token。
4. **报表按来源给覆盖。** 输入最终覆盖、输出最终覆盖及双侧最终覆盖分别除以已结算调用数（含可识别的 `abandoned`）。输入/输出比只用同时有两侧最终值的同批调用汇总后相除；输出总和为零时不展示比值。两列已知用量各自写明覆盖调用数；部分观察量、无调用级能力的安装日和截顶日分开报。已观测用量不写成账单。

发布前同一组合成调用从**提供方返回 → 引擎或适配器 → 已封账日包 → Worker → 查询**逐层对账。样本包含有缓存的正常流、工具多步、最终字段缺失、明确零输出、取消有/无最终用量、重连重播、实际重试、远程旧协议、跨午夜和截顶。对同批样本，所有可观测调用的分类与数值应逐层一致；无法观察的路径标明在哪一层停止。历史旧表没有字段状态，无法据此回填缺失的输出。

## 埋点清单

这是 App 内部触发点注册表，上报单位是按日固定桶，不是逐条事件。业务动作由接受它的模块负责结算；用户动作、实际模型调用与后台任务不混为一个次数。成功率用同一批尝试的终态作分母，不拿不同天的开始数和结束数相除。

| 优先 | 埋点及触发 | 报表用途与边界 |
| --- | --- | --- |
| P0 | `app.foreground_day`、`cohort.first_foreground`：实际前台；日内首次和本周期开启后首次分别记。 | DAU、机型覆盖、D1/D7。 |
| P0 | `runtime.launch`、`remote.connect`：实际发起本机启动或远程连接，探针就绪/应用层握手成功时结算。 | 成功/失败/取消/未知、启动和连接耗时；本机启动模式、远程传输类型和初连/重连分组。 |
| P0 | `chat.turn`、`chat.first_visible_text`：发起聊天，到匹配的最终轮次状态；首个可见非空回复时单独取时。 | 成功、取消、阻断、错误、达到用量上限、未知；首字时间只取出现正文的轮次，另报这个覆盖率。推理和工具帧不是正文。 |
| P0 | `token.call`：计量所有者按真实模型调用结算。 | 主聊天、酒馆、伙伴分别报告用量、缓存和字段覆盖，详见上节。 |
| P1 | `phone.task`、`phone.stop`：原生确认关联的运行/停止结果，按 run ID 与 generation 配对。 | 成功、失败、停止、未知；可确认的停止来源和清理失败分开计。仅看到 idle 不算成功。 |
| P1 | `update.flow`：发现更新、下载、校验、交给安装器、有可验证的安装结果；下次前台看到目标版本单独计。 | 每阶段按实际尝试及权威回执结算；打开安装器只算交接，不能当安装成功。 |
| P1 | `tavern.turn`、`companion.turn`、`companion.room_open`、`call.session`：用户回合终态、房间实际呈现、通话发起/连接/结束。 | 回合结果及首字、房间使用安装数、通话接通与时长。只有开麦信号时不算接通；没有可靠连接信号报未知。 |
| P2 | `plugin.install`、`plugin.run`：插件宿主确认安装或执行结果，按内置/第三方；`onboarding.steps`：记录进入路径、就绪、首个可见回复。 | 插件结果、耗时和安装数；引导按同一日进入路径的 cohort 算达成，已有连接和主动跳过单列。 |
| P2 | `app.stability`：平台提供可信进程退出原因、且现有统计范围支持时记。 | 仅报可确认的异常退出次数及覆盖。不从非正常关闭推断崩溃，不上报堆栈。 |

事件结果按完成日归桶，跨午夜的尝试计入完成时的 UTC+8 日期。日包只发送已结束的统计日，不等待跨日未完成的尝试；已封账快照不追写。Token 按调用可观测结算日计量，因此不因用户轮次先封账而丢掉 Token。更新交给外部安装器之后若没有可关联回执，只报版本观察或未知。引导按首次进入路径后 24 小时是否达成汇总；独立写入该窗口结算日，报表按日差 `0/1` 还原进入日，进入日满 24 小时并过了结算日的补报窗口后才计算达成率。

失败原因由调用端映射到固定枚举 `permission` / `network` / `timeout` / `auth` / `provider_limit` / `runtime` / `integrity` / `unsupported` / `other`，取消和未知单列为结果。耗时用 `≤0.25s`、`≤0.5s`、`≤1s`、`≤2s`、`≤5s`、`≤10s`、`≤30s`、`≤60s`、`≤180s`、`>180s` 的互斥桶。P50/P95 只给命中区间，附样本量和有效计时覆盖，不从桶内插出精确小数。

## 日包、迁移与隐私

- 增加 `POST /api/usage/v4` 和单独的数据集，继续维护旧路由 `/api/usage/v1` 和 `dshgo_usage` 的列定义。各协议独立记账及重试，同一 v4 安装日只生成一份不可变快照。旧 Worker 对新路由返回 `404` 时暂停当天的 v4，旧路由照常；`400` 作为协议问题暴露，不靠降级掩盖字段错误。超过七天的待发快照按日删除。
- 顶层只允许协议版本、统计日、安装随机 ID、版本/平台、现有受限设备字段和注册表定义的固定行；关闭态的包省略 `chat_log` 与 `extra`，只留 base 行。每份包最多 16 KiB、最多 48 个写点（包含基准行），每行最多 20 个数值槽。数值的列位置、单位、枚举、上限和允许组合由注册表固定；App 先按上限截顶并标记，Worker 校验整包，拒绝未知行、重复键和越界值。P0 实现同时交付注册表和最大日包测试；新组占用通过同一个上限检查。
- 每个日包有 `base` 及预期行掩码。适用但未触发得出明确的零事件；不适用/无能力的来源标 `unavailable`；预期写入而查不到的行是缺行。查询按 `(统计日, HMAC 安装, 固定行类型)` 去重后聚合。同一个键重传的内容必须一致；同步写失败要能整包重试，不预先写成功去重标记。Cloudflare 接收后异步写入，`204` 不是逐点持久化证明；可见基准缺失、预期行缺失和截顶单列。整份报告若不可见，就无法从数据集自身估算损失。
- 报表附带读取覆盖和抽样状况。发现抽样、查询截断或未验证的迁移断点时，将安装数、留存标为不完整或不可比，不能用 `_sample_interval` 简单放大去重人数。新旧账号分区间验收，只有统计日、身份命名空间和数据覆盖都可验证时才连续算跨日留存；密钥轮换或权限不足就分段，避免把老安装当流失或新增。[Cloudflare 写入说明](https://developers.cloudflare.com/analytics/analytics-engine/get-started/)和 [SQL API](https://developers.cloudflare.com/analytics/analytics-engine/sql-api/) 是容量和采样约束；长期趋势如需要，仅另存聚合结果。
- 新版说明先更新中英文文案和用户指南；统计默认开启，说明与提示只做告知，不阻塞记账。未启用既有统计的平台不随这次改动开启。关闭后功能与模型统计立刻停记，清空其待发日包、关联记账状态和旧统计的随机 ID；Android 的日活计数不中断，关闭态日包只含 base 行（前台位、首日前台位）、统计日、匿名安装 ID 与 App 版本，不含机型、功能、内容或地址。等待中的任务检查账本代际，重新打开后不续传旧包。已经被服务器接收的在途请求无法撤回。
- 安装 ID 只通过 TLS 日包送给 Worker，在独立上下文 HMAC 后才入库。不上报原始安装 ID、IP、任务/会话/调用 ID、账户、地址、URL、插件名、内容、音频、错误原文或堆栈；旧设备维度只放基准行。分析报表输出聚合，不导出用于去重的安装标识，不在仓库保存生产密钥或真实遥测样本。

P0 的固定行按下表留容量。网络、启动模式等分析维度每次选一个固定类别归桶；不要再叠版本、机型等生成笛卡尔积。每种重复行用注册表中的固定类别作行类型后缀，封账时生成预期行掩码。

| 行 | 每日最多 | 数值内容 |
| --- | ---: | --- |
| `base` | 1 | 前台位、首日前台位、采集能力及预期行掩码、截顶标记。 |
| `token_counts` | 4 | 主聊天本机、主聊天远程、酒馆、伙伴各一；已结算数、两侧各五类状态计数、双侧覆盖数。 |
| `token_values` | 4 | 同上；两侧最终和、同批双侧最终和、两侧部分和、输入缓存三项及有效调用数、可拆分的推理和及有效调用数。单独标记有截顶的值。 |
| `runtime_result` / `runtime_latency` | 4 + 4 | 预留四个本机启动模式桶；每桶结果/失败原因、成功延迟。 |
| `remote_result` / `remote_latency` | 6 + 6 | 最多三个互斥传输类别，各自初连/重连；每桶结果/失败原因、成功延迟。 |
| `chat_result` / `chat_first_text` | 2 + 2 | 本机和远程；结果/失败原因、首字延迟。 |

P0 满包最多 33 点，剩余 15 点留给后续阶段；若后续固定行排不下，先合并不需要分组的桶，仍超出再做有版本的预算变更。

## 实现顺序和验证

1. **日包与报表基座。** Worker 独立数据集、校验、App 封账、合成报表。先用无机型、零事件、旧 Worker、跨日补发、抽样、重试和跨版本 cohort 的夹具验证。先发布兼容 Worker、再由新 App 送数据；开发流量只进测试环境。
2. **主聊天、酒馆、伙伴 Token 以及启动、远程和聊天。** 先做上述逐层对账；同时验证带/不带用量能力的远程主机。报表先标覆盖，再展示用量和成功率。
3. **手机操控、更新、通话及其余功能。** Android 真机验证机型缺失时仍可上报、同一个启动/任务只结一次、安装器交接与真实回执确实分开，以及离线补报和关闭开关。插件、引导和稳定性按 P2 接入，拿不到可靠终态的路径保持未知。桌面测试覆盖协议、账本和报表，不替代真机结果。

### 当前实现与核验口径

Android 从首次前台起发送独立 v4 日包，开关关闭时这个包只含 base 行。基准行含实际前台及本统计周期首日前台；字段缺失仍可上报。关闭开关会清理功能与模型统计的本地账本，只保留日活位；旧路由照常，报表不把两个协议相加。

- 主聊天：核过固定版 DSH 的 Messages 适配器、流组装器和会话日志。适配器原来初始化输出为 0，在 message_stop 只发一条归一化用量；尾帧省略输出时无法区分缺失与零。新适配器保留提供方实际报告的字段，随流保存中间观测；只在完整消息中算最终量。旧 Token 数值仍供现有界面读取。其他适配器和远程旧版未必提供同级证据。
- 酒馆：每次实际 HTTP 尝试（含重试和工具后的新请求）结算一次，含未报用量、明确零和已观察到的部分量。伙伴：轻量对话和自适应的 Messages 请求在 message_stop 结算，断流只记部分量；不把 message_start 的输出计成最终值。
- 本机启动：观测 Android 原生 starting 至运行就绪、错误或停止，记录可识别的 Direct／PRoot 模式及成功耗时。远程：SSH 与 DSH Remote 各分初连／重连，按连接周期计算（含该周期中的退避与重试），应用层握手完成才视为就绪。时长按单调时钟分桶。未观察到开始、App 进程中断、后台丢失的主聊天日志仍不可见；不回填历史漏量。
- 主聊天回合记录 App 观察到的开始与匹配的结束；首字从回合开始到同一回合第一个非空正文流片，未见正文单列。手机任务只在原生结束的 run ID 与 generation 匹配时记结果；更新从下载开始到校验就绪、失败或取消，不把就绪视作安装成功。同一安装尝试只有重新读到安装版本变化才记成功；交给安装器但结果不明时归未知。语音通话以收到并开始播放模型回复确认链路，按结束原因结算，单独记录确认后的时长；只开麦不算接通。插件安装只记队列实际处理并结算的任务；本机插件执行只记实际进入处理器的调用，延迟交付按流上的成功、失败或取消结算，连接中断无法核实时标未知。引导按本机、远程、酒馆记录本次流程完成。Android 11 起读取系统确认的崩溃和 ANR 并按观察日累计；较旧系统不采集，不带堆栈或进程名。本机桥接层订阅会话写入事件，覆盖没有聊天页面订阅但已写会话日志的后台任务；启用后每分钟续租，关闭时清空，App 未续约的窗口不采集。独立模型调用若不写会话日志仍不可见。Pi AI 对有原始流钩子的常见协议保留输出存在性；仅有归一化数据的路径无法证明零。远程沿用当前 App 的日志观测。引导达到首个可见回复的 24 小时漏斗仍未接入。

用 [usage-v4-report.py](../../services/share-worker/scripts/usage-v4-report.py) 查询。`--days 14` 输出 UTC+8 的结束日；`--cohort YYYY-MM-DD`（可重复传入）计算统计启用 cohort；`--dry-run` 只看 SQL。正式查询用 `CF_ACCOUNT_ID` 和带 Account Analytics Read 的 `CF_TOKEN_FILE`。输出仅包含聚合、按来源去重和分开汇总最终／部分用量。留存只在目标日补发窗口关闭、有可见目标日且查询未观察到抽样时计算。
