# 手机技能：从做过的事里学（2026-11-23 重做）

用户的话：「Mika 沉淀成 skill 的这个系统，对 AI 多次使用提高熟练度很有用，重点学一下，并且默认开启。现在太犄角旮旯了，应该在手机操控菜单里单独列出来，还可以点进去详细管理 skill。手机操控结束之后，让用户自己选择是否保存这个 skill，以及进行修改。」

## 0. 现在的问题（main be4609ce2 上的实现）

调研结论（逐条核对过代码）：

1. **默认关**（`PhoneControl.skillSavePrompt` 默认 false），开关和候选藏在手机操控页「更多设置」折叠的第三张卡里，设置搜索搜不到。
2. **只在停在手机操控页时才问**（`PhoneSkillAutoPrompt` 包在手机页外面）。任务多半从聊天发起，结束时人在聊天页，基本不会被问到。
3. **存下来的东西没用**：`PhoneSkillDraft.render` 用模板拼出一份全是 `{{goal}}`、`{{target_n}}` 占位符的 Markdown；编辑框里填的目标、前提、检查点**不会写进去**；名字是 `phone-task-<32 位十六进制>`。
4. **模型以后看不到它**：frontmatter 写死 `disable-model-invocation: true`，手机 MCP 不带 instructions，回放描述表 `PhoneSkillReplayApps.descriptors` 是空的，所以「用得越多越熟练」根本不存在。
5. 候选只在内存里，最多 8 个，引擎重启就丢；一步出错或用过 `tap_xy` 整条就不能起草。
6. 存下以后不能改、不能改名、不能删、不能停用；通用技能页只能看。

所以这次不是挪个入口，而是按 Mika 的主线重做「学 → 你收下 → 试用 → 常用」，再按 DSH Go 的特点改。

## 1. 学 Mika 什么、改什么

学（Mika a40f6a98 的 `learn/skills`）：

- **技能是给模型读的自然语言文档，不是步骤宏。** 固定五节：入口、步骤、容易出错的地方、怎样算办成、什么时候停下交给你。参数写成 `<参数>`。
- **起草和生效分开**：草稿要用户收下；收下后先**试用**（注入时标明还没验证过），用它办成一次转**常用**，最近几次不灵就**自动停用**，这些事都告诉用户。
- **谁照着做了谁背结果**：读过技能且之后在它写的 App 里成功动过手才算「照着做」；分不清就不记。模型出错、网络、额度用完不算技能的错。
- **同一类事只留一份**：起草时把已有技能清单给模型，它判断是同一类事就写成对那份的**更新**；收下时显示改了哪几行，原文被改过就拒绝覆盖。
- **模型只看抽象过的动作清单**：输入的字、网址查询串、数字一律占位，从源头看不到具体值；再加脱敏兜底。
- **技能索引常驻上下文、按需读全文**：任务开始时模型拿到所有可用技能的一行描述，要用时再读全文。
- 每次改写、删除都留旧版，可以「恢复上一版」。

DSH Go 自己的改法：

- **问在你看得到的地方**：任务结束时在**这次任务所在的对话里**出一张卡（不是只有手机页才问），另外在「手机技能」页的「待确认」里留着；App 不在前台时发一条普通通知。
- **默认开**：「从做过的事里学」默认开。开着也不会自己生效——收下才算数，这是用户要的「让用户自己选择是否保存」。
- **门槛更低**：Mika 要至少 5 步，我们 3 步就学（手机上很多事 3 步就完）；用过 `tap_xy` 不再一票否决，动作清单里记成「点了屏幕上的某处」。
- **名字可读**：`phone-<英文短名>`，显示名是中文；可以改显示名。
- **编辑就是改原文**：五节各一个文本框，所见即所存；不再有「自由文字会替换成参数」这种摆设。
- **不做**：Mika 的技能市场、导入、示教、App 知识、确定性路线回放（我们已有的回放骨架保留不动，这一期不接）。

## 2. 技能文件

存在引擎的用户技能目录 `<DSH_HOME>/skills/phone-<name>/SKILL.md`，和别的技能同一套机制，这样引擎本来的技能列表、`/名字` 调用都能用。

```markdown
---
name: phone-send-wechat-voice
description: 在微信里给某人发语音消息（打开对话、按住说话、松开发送）
when-to-use: 用户要在微信里给联系人发语音时
display: 微信发语音
apps: [com.tencent.mm]
source: learned            # learned | written（你让 DSH 写的）
state: trial               # pending 不落在这里；trial | active | suspended
learned-from: <会话 id>/<任务 id>
---

## 入口
……
## 步骤
1. ……
## 容易出错的地方
- ……
## 怎样算办成
……
## 什么时候停下交给你
……
```

- `state` 和结果记录另存一份 `.state.json`（同目录），不让模型改；frontmatter 里的 `state` 只是给人看的镜像。
- 正文不超过 4000 字。五节缺一节、提到不存在的手机工具、命中敏感词（复用 `SensitiveWords`）的草稿直接丢掉，不打扰用户。
- 旧版本存 `<DSH_HOME>/skills/.archive/<name>/<时间>.md`，每个技能最多留 5 份。
- 已有的 `phone-task-<hex>` 技能：升级时不动、照旧在技能页里；手机技能页把它们列在「早期存下的」里，可以删。

## 3. 状态

```
（任务办成）→ 草稿（待确认）──收下──→ 试用 ──用它办成 1 次──→ 常用
                     └──不要──→ 丢掉          └─最近 3 次里 2 次不灵─→ 停用（可恢复）
常用 ──最近 3 次里 2 次不灵──→ 停用
```

- **待确认**：最多留 20 份，30 天没处理自动丢（丢之前不提醒，草稿本来就是可有可无的）。
- **试用**：进技能索引，描述前加「（试用中，还没用它办成过事，照做时核对结果）」。
- **不灵**：照着它做、任务没办成或你中途接管 / 拒绝确认 / 停止。模型报错、网络断、额度用完记「不算」。
- 停用、恢复、删除都只能你在页面上做，模型不能改技能的状态；你在对话里说「把发语音那个技能改成……」，DSH 可以起草一份**更新草稿**，同样要你收下。

## 4. 起草（后端，交给 Pro）

- **什么时候**：一个手机任务结束、并且满足：模型正常结束（`completion == completed`）、没被取消、你没在中途接管或拒绝确认、有效动作 ≥ 3、这次不是照着某份技能做成的（那种记成那份技能的「办成一次」）、「从做过的事里学」开着。
- **谁来写**：用这次任务**同一个模型和服务商**单独调一次，不带工具，不进对话记录，不计入对话的上下文。离线或失败就不起草，不重试。
- **给模型什么**：目标（用户这次的原话，引号里的值和数字已占位）、DSH 的最终回答、动作清单（`PhoneTaskTrace` 已有的抽象：动作类型、控件角色、公开动作词、在哪个 App、生效/没变化/出错；输入的字一律 `<输入内容>`，坐标不给）、已有手机技能（常用 + 试用 + 待确认）的「名字：一行描述」清单。
- **它返回**：新技能全文，或对某份的更新（头部 `updates: <name>`），或「不值得学」（一次性的事、太短、看不出规律）。
- **兜底脱敏**：引号里的值、输入的字、金额、≥2 位数字串换成 `<参数>`（App 名里的数字保留）。

## 5. 用起来（后端，交给 Pro）

- **索引**：手机任务开始时，模型的上下文里有一段「你在这台手机上学会的做法」：常用和试用的技能每份一行「名字（显示名）：描述」，常用在前。超过 40 份时按任务文字和 `apps` 匹配取前 40。这一段不随上下文裁剪丢掉。
- **读全文**：用引擎现有的技能读取（`/skill` 或技能工具，Pro 选现成的那条），不新增手机工具；做不到再在手机 MCP 里加一个只读的 `skill_read`。
- **记结果**：按「谁照着做了谁背结果」记到 `.state.json`：最近 5 次（办成 / 不灵 / 不算），触发转常用、自动停用。
- **告诉你**：转常用、自动停用在这次任务所在的对话里出一行小字（「『微信发语音』用它办成了事，转为常用」「『微信发语音』最近不灵，先停用了 · 恢复」）。

## 6. 界面（我来做）

### 6.1 入口：手机操控页单独一行

在手机操控页的主列表里（不在「更多设置」折叠里），和「悬浮条」「不打扰模式」同级：

> **手机技能** · 已学会 6 项 · 2 份待确认 ›

待确认数为 0 时只写「已学会 N 项」；一项都没有时写「做过的事会在这里变成技能」。设置搜索能搜到（「技能」「学会」「熟练」「沉淀」）。

### 6.2 手机技能页

顶部一个开关：**从做过的事里学**（默认开）——「手机操控办成的事会起草成技能，你收下才会用」。

分段：**我的技能 · 待确认 N**。

- **我的技能**：每行是应用图标（圆角方块）+ 显示名 + 描述一行 + 状态小字（「常用 · 用了 12 次」「试用中 · 还没用它办成过事」「已停用 · 最近不灵」「你让 DSH 写的」），右侧开关是停用 / 恢复。点开进详情。
- **待确认**：每份一张卡：显示名、描述、来自哪次任务（点了跳到那个对话）、「收下试用 / 改一改 / 不要」。更新草稿显示「要改『微信发语音』：」加 + / − 行对比，按钮是「收下这次修改 / 改一改 / 不要」。
- **早期存下的**（只有旧 `phone-task-*` 时出现）：可以删。

### 6.3 技能详情 / 编辑

- 头：图标、显示名（可改）、状态、最近 5 次的结果点（绿 / 红 / 灰）。
- 正文按五节显示，「改一改」后每节变成文本框，描述和「什么时候用」也可以改；保存时跑同一套校验和脱敏，不过就说哪里不行。
- 底部：「在对话里用」（把 `/名字` 放进输入框）、「恢复上一版」（有旧版时）、「删除」（确认一次，说清删了模型就不再用它）。

### 6.4 任务结束时的卡

在这次任务所在的对话里，DSH 最后一条回复下面：

> ✦ **DSH 学会了一个新做法：微信发语音**
> 在微信里给某人发语音消息（打开对话、按住说话、松开发送）
> [收下] [改一改] [不要]

- 卡片在草稿起好后出现（起草要几秒，期间不占位）；你不处理它也一直在「待确认」里。
- App 不在前台时：发一条普通通知「DSH 学会了一个新做法：微信发语音 · 点开看看」，点开到这张卡。
- 「不要」之后卡收成一行「没有存」，可以撤销 5 秒。

## 7. 原生 ↔ Dart 通道（Pro 和我按这个对接）

`dsh/phone` MethodChannel 新增（旧的 `skillDrafts`/`openSkillDraft`/`saveSkillDraft` 一类在新流程接好后删掉）：

| 方法 | 入参 | 返回 |
|---|---|---|
| `skills.list` | — | `{learn: bool, skills: [Skill], drafts: [Draft], legacy: [{name, path}]}` |
| `skills.get` | `{name}` | `Skill`，含 `body`（全文）、`sections`（五节文本）、`history`（旧版时间列表） |
| `skills.setLearn` | `{on}` | `{learn}` |
| `skills.accept` | `{draftId, edited?: Sections}` | `Skill` 或 `{error: 'changed'|'invalid'|'sensitive', detail}` |
| `skills.discard` | `{draftId}` | `{}` |
| `skills.save` | `{name, display?, description?, whenToUse?, sections?}` | `Skill` 或 error 同上 |
| `skills.setEnabled` | `{name, on}` | `Skill` |
| `skills.restore` | `{name}` | `Skill`（恢复上一版） |
| `skills.delete` | `{name}` | `{}` |

```
Skill  = {name, display, description, whenToUse, apps: [pkg], source, state: trial|active|suspended,
          uses: int, recent: [ok|miss|void], updatedAt, learnedFrom?: {sessionId, taskId}}
Draft  = {id, kind: new|update, target?: name, display, description, sections, diff?: [{op:'+'|'-'|' ', text}],
          createdAt, from: {sessionId, taskId}}
```

事件（`dsh/phone/events` 里已有的流加两种）：`skillDraft {draft}`（新草稿起好）、`skillOutcome {name, state, change: promoted|suspended}`。
