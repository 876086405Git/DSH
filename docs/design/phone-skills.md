# 手机技能：从做过的事里学（2026-11-23 重做）

用户的话：「Mika 沉淀成 skill 的这个系统，对 AI 多次使用提高熟练度很有用，重点学一下，并且默认开启。现在太犄角旮旯了，应该在手机操控菜单里单独列出来，还可以点进去详细管理 skill。手机操控结束之后，让用户自己选择是否保存这个 skill，以及进行修改。」

## 0. 现在的问题（main be4609ce2 上的实现）

调研结论（逐条核对过代码）：

1. **默认关**（`PhoneControl.skillSavePrompt` 默认 false），开关和候选藏在手机操控页「更多设置」折叠的第三张卡里，设置搜索搜不到。
2. **只在停在手机操控页时才问**（`PhoneSkillAutoPrompt` 包在手机页外面）。任务多半从聊天发起，结束时人在聊天页，基本不会被问到。
3. **存下来的东西没用**：`PhoneSkillDraft.render` 用模板拼出一份全是 `{{goal}}`、`{{target_n}}` 占位符的 Markdown；编辑框里填的目标、前提、检查点**不会写进去**；名字是 `phone-task-<32 位十六进制>`。
4. **模型以后看不到它**：frontmatter 写死 `disable-model-invocation: true`，手机 MCP 不带 instructions，回放描述表 `PhoneSkillReplayApps.descriptors` 是空的，所以「用得越多越熟练」根本不存在。
5. 候选只在内存里，最多 8 个，引擎重启就丢；一步出错或用过 `tap_xy` 整条就不能起草。
6. 存下以后不能改、不能改名、不能删、不能停用；通用技能页只能看。

所以这次不是挪个入口，而是按 Mika 的主线重做「学 → 你收下 → 试用 → 常用」，再按 DSH Go 的特点改。

## 1. 学 Mika 什么、改什么

学（Mika a40f6a98 的 `learn/skills`）：

- **技能是给模型读的自然语言文档，不是步骤宏。** 固定五节：入口、步骤、容易出错的地方、怎样算办成、什么时候停下交给你。参数写成 `<参数>`。
- **起草和生效分开**：草稿要用户收下；收下后先**试用**（注入时标明还没验证过），用它办成一次转**常用**，最近几次不灵就**自动停用**，这些事都告诉用户。
- **谁照着做了谁背结果**：读过技能且之后在它写的 App 里成功动过手才算「照着做」；分不清就不记。模型出错、网络、额度用完不算技能的错。
- **同一类事只留一份**：起草时把已有技能清单给模型，它判断是同一类事就写成对那份的**更新**；收下时显示改了哪几行，原文被改过就拒绝覆盖。
- **模型结合目标理解做法**：起草时读取本次目标原话、DSH 的最终回答、抽象动作清单和已有技能短引用，把具体值写成参数。原生在草稿落盘前再次脱敏。
- **技能索引常驻上下文、按需读全文**：任务需要手机工具时，模型拿到最多 40 份匹配技能的一行描述，要用时再读全文。
- 每次改写、删除都留旧版，可以「恢复上一版」。

DSH Go 自己的改法：

- **问在你看得到的地方**：任务结束时在**这次任务所在的对话里**出一张卡（不是只有手机页才问），另外在「手机技能」页的「待确认」里留着；App 不在前台时发一条普通通知。
- **默认开**：「从做过的事里学」默认开。开着也不会自己生效——收下才算数，这是用户要的「让用户自己选择是否保存」。
- **门槛更低**：Mika 要至少 5 步，我们 3 步就学（手机上很多事 3 步就完）；用过 `tap_xy` 不再一票否决，动作清单里记成「点了屏幕上的某处」。
- **名字可读**：`phone-<英文短名>`，显示名与五节正文随 App 语言使用中文或英文；用户可以改显示名。
- **编辑就是改原文**：五节各一个文本框，所见即所存；不再有「自由文字会替换成参数」这种摆设。
- **不做**：Mika 的技能市场、导入、示教、App 知识、确定性路线回放（我们已有的回放骨架保留不动，这一期不接）。

## 2. 技能文件

收下后的技能投影到引擎用户技能目录 `<DSH_HOME>/skills/phone-<name>/SKILL.md`。有本机手机工具的对话可通过技能列表和 `/名字` 使用它。

```markdown
---
name: phone-send-wechat-voice
description: 在微信里给某人发语音消息（打开对话、按住说话、松开发送）
when-to-use: 用户要在微信里给联系人发语音时
display: 微信发语音
apps: [com.tencent.mm]
source: learned
state: trial
disable-model-invocation: true
user-invocable: false
learned-from: "session-example/7"
---

## 入口
……
## 步骤
1. ……
## 容易出错的地方
- ……
## 怎样算办成
……
## 什么时候停下交给你
……
```

- 任务起草写入 `source: learned` 和 `learned-from`（对话和手机任务编号）。用户在技能页修改正文。
- Android 私有目录保存已确认正文、草稿、状态和版本历史。引擎技能目录里的 `SKILL.md` 和 `.state.json` 是发布给引擎和人的副本。文件投影始终关闭通用文件技能提供者的模型和用户调用，手机技能提供者独立依据原生状态开放 `skill` 和 `/名字`。状态和版本资格以原生记录为准。直接编辑引擎副本不会让一项技能转为常用。App 和本地引擎共享 Android UID，拥有同一 UID 的任意代码仍处于同一操作系统权限边界。
- `name` 由小写英文单词及连字符组成，总长不超过 64。正文含标题不超过 4000 个 Unicode 字符。中文五节见上例。英文为 Entry、Steps、Pitfalls、Success criteria、When to hand off，顺序固定。原生拒绝缺节、空节、未知的明确手机工具引用，以及命中 `SensitiveWords` 的秘密字段词的草稿。「发送」「提交」等需要确认的动作可以描述，实际操作仍按本次策略确认。
- 模型输出和用户编辑在写入前共用校验和脱敏。引号内的值、网址、电邮、金额、电话和成组数字等替为 `<参数>` 或 `<parameter>`，允许的 App 包名可保留自身数字。
- 每份技能的旧版保存在 `<DSH_HOME>/skills/.archive/<name>/<时间>.md`，最多 5 份。可恢复上一版。删除受管技能后，`skills.list.archived` 仍给出可恢复的名字。
- 升级时保留已有的 `phone-task-<hex>`。它们单列在「早期存下的」，不进入学习索引。删除时只归档脱敏后的 Markdown，旧回放数据不用于新技能。

## 3. 状态

```
（任务办成）→ 草稿（待确认）──收下──→ 试用 ──用它办成 1 次──→ 常用
                     └──不要──→ 丢掉          └─最近 3 次里 2 次不灵─→ 停用（可恢复）
常用 ──最近 3 次里 2 次不灵──→ 停用
```

- **待确认草稿**最多留 20 份，保留 30 天，引擎重启后继续可审。放弃草稿不会移除一份已经收下的技能。
- **试用技能**进入可用索引，标明需重新核对结果。试用技能第一次有归属的成功转为常用。关闭「从做过的事里学」会停止从手机任务自动起草。已收下的技能保持原状态。
- **累计使用次数**包括有归属的办成（`ok`）、不灵（`miss`）、不算（`void`）。详情显示最近 5 次。判定自动停用的窗口只取最近 3 次可评价的 `ok/miss`，其中累计 2 次 `miss` 即停用。模型报错、网络或额度中断等不推进失败窗口。
- 停用原因随状态保存，用户手动停用记为 `manual`，失败窗口触发停用记为 `misses`。原因未知的旧记录保持为空。人工恢复会清空原因和失败窗口。曾办成的恢复为常用，其余恢复为试用。模型没有更改状态、接受草稿或删除技能的管理工具。

## 4. 起草

- 本机 Android 手机任务正常完成并通过原生归属校验后，宿主检查起草资格。学习已开启，驱动至少接受了 3 个动作，任务没有取消、用户接管或拒绝确认，且未发现已有技能的使用或归属歧义时，才进入起草。一次普通动作返回错误仍可记录后续动作。操作秘密输入控件、不确定的副作用、摘要截断等会使摘要不能用于起草。
- 引擎向原任务实际使用的模型和服务商单独发起一次起草请求。凭据由原服务商适配器解析。请求不带工具和对话历史，回复不进入原对话。无法绑定原任务实际路由、被取消、离线或失败时，手机技能宿主放弃这次起草，不重新提交请求。第三方服务商适配器内部的请求次数由适配器决定。
- 起草请求的一条用户消息包含本轮目标原话（`goal`）和 DSH 最终答复（`finalAnswer`）。它们由引擎从这次对话取出，用来判断可复用的任务和适用时机。原生动作摘要只交付包名、公开控件动作词与动作种类，不含屏幕原文、图片、坐标或控件编号。输入动作只写 `<输入内容>` 或 `<input>`，`tap_xy` 只表示点过屏幕上某处。结果区分可比观察中的界面变化、无变化、驱动接受但未验证、过期拒绝和错误。界面变化本身不能证明业务办成。
- 常用、试用及待确认草稿用临时引用（如 `S1`）标记，列出包名和已通过原生校验脱敏的显示名、描述、适用时机，每栏最多 96 个 Unicode 字符。清单省略文件名、版本指纹及正文。提示要求把具体人名、号码、金额、地址和文字内容改为参数，包括显示名与描述。原生对输出再做秘密字段检查、引号值和数字等的脱敏，用户收下前可以审阅。
- 新技能返回完整五节 Markdown。更新用 `updates: S1` 引用候选。不值得学返回 `SKIP`。模型提供的状态或来源不能改变原生记录。接收时把临时引用还原为原技能，按起草前的原文 SHA-256 绑定，逐行计算差异。用户收下前若目标有变，返回 `changed`，原技能与待审草稿均保留。更新待确认草稿同样检查其版本，替换成功后使用新的草稿 ID。

## 5. 用起来

- 具有本机手机工具的任务可以获得索引。试用与常用每份一行，包括名称、显示名、描述和试用提示。匹配任务文字与 App 后最多选 40 份。展示时常用排在试用前，同组按匹配、更新时间和名称排序。索引是每次构建模型请求时提供的上下文，不依赖早期聊天消息在压缩后仍保留。
- 读取全文使用引擎已有的 `skill` 工具和 `/名字`。Android 受管技能提供者优先于同名文件条目，为停用条目保留不可调用的位置，使文件系统提供者不会将同一名字重新暴露。自动索引之外的其他已启用技能仍可由用户明确以 `/名字` 调用。
- 记结果时，正文与登记版本须一致并已进入产生动作的模型请求。之后还须在技能声明的 App 中有驱动已接受的真实操作。只看到索引、同一批并行发起读取和点击、只打开 App 或模型自称用过均不足以归属。多份技能都可能解释同一动作且无法区分时不计。正常结束、主动接管或明确否决、运行出错分别使用宿主和原生证据判定，无法判定不责罚技能。
- 首次办成转常用或自动停用时，原生事件带上本次对话和任务 ID，供界面在对应对话显示。草稿产生也带来源，界面可重新查询持久化待确认列表。

## 6. 界面（我来做）

### 6.1 入口：手机操控页单独一行

在手机操控页的主列表里（不在「更多设置」折叠里），和「悬浮条」「不打扰模式」同级：

> **手机技能** · 已学会 6 项 · 2 份待确认 ›

待确认数为 0 时只写「已学会 N 项」；一项都没有时写「做过的事会在这里变成技能」。设置搜索能搜到（「技能」「学会」「熟练」「沉淀」）。

### 6.2 手机技能页

顶部一个开关：**从做过的事里学**（默认开）——「手机操控办成的事会起草成技能，你收下才会用」。

分段：**我的技能 · 待确认 N**。

- **我的技能**：每行是应用图标（圆角方块）+ 显示名 + 描述一行 + 状态小字（「常用 · 用了 12 次」「试用中 · 还没用它办成过事」「已停用」「已停用 · 最近不灵」），仅 `misses` 显示「最近不灵」。右侧开关是停用 / 恢复。点开进详情。
- **待确认**：每份一张卡：显示名、描述、来自哪次任务（点了跳到那个对话）、「收下试用 / 改一改 / 不要」。更新草稿显示「要改『微信发语音』：」加 + / − 行对比，按钮是「收下这次修改 / 改一改 / 不要」。
- **早期存下的**（只有旧 `phone-task-*` 时出现）：可以删。

### 6.3 技能详情 / 编辑

- 头：图标、显示名（可改）、状态、最近 5 次的结果点（绿 / 红 / 灰）。
- 正文按五节显示，「改一改」后每节变成文本框，描述和「什么时候用」也可以改；保存时跑同一套校验和脱敏，不过就说哪里不行。
- 底部：「在对话里用」（把 `/名字` 放进输入框）、「恢复上一版」（有旧版时）、「删除」（确认一次，说清删了模型就不再用它）。

### 6.4 任务结束时的卡

草稿卡按来源会话 ID 显示在对应对话的输入框上方。

> ✦ **DSH 学会了一个新做法：微信发语音**
> 在微信里给某人发语音消息（打开对话、按住说话、松开发送）
> [收下] [改一改] [不要]

- 卡片在草稿起好后出现（起草要几秒，期间不占位）；你不处理它也一直在「待确认」里。
- App 不在前台时：发一条普通通知「DSH 学会了一个新做法：微信发语音 · 点开看看」，点开到这张卡。
- 「不要」之后卡收成一行「没有存」，可以撤销 5 秒。

## 7. 原生 ↔ Dart 通道（Pro 和我按这个对接）

管理方法通过 `dsh/phone` MethodChannel 暴露，旧的模板候选方法已移除。

| 方法 | 入参 | 返回 |
|---|---|---|
| `skills.list` | — | `{learn: bool, skills: [Skill], drafts: [Draft], legacy: [{name, path}], archived: [name]}` |
| `skills.get` | `{name}` | `Skill`，含 `body`（全文）、`sections`（五节文本）、`history`（旧版时间列表） |
| `skills.setLearn` | `{on}` | `{learn}` |
| `skills.accept` | `{draftId, edited?: Sections}` | `Skill` 或 `{error: 'changed'|'invalid'|'sensitive', detail}` |
| `skills.discard` | `{draftId}` | `{}` |
| `skills.save` | `{name, display?, description?, whenToUse?, sections?}` | `Skill` 或 error 同上 |
| `skills.setEnabled` | `{name, on}` | `Skill` |
| `skills.restore` | `{name}` | `Skill`（恢复上一版） |
| `skills.delete` | `{name}` | `{}` |

```
Skill  = {name, display, description, whenToUse, apps: [pkg], source, state: trial|active|suspended,
          suspensionReason: manual|misses|null, uses: int, recent: [ok|miss|void], updatedAt, learnedFrom?: {sessionId, taskId}}
Draft  = {id, name, kind: new|update, target?: name, display, description, whenToUse, apps: [pkg],
          sections, body, baseFingerprint?, diff?: [{op:'+'|'-'|' ', text}], createdAt, from: {sessionId, taskId}}
Sections = {entry, steps, pitfalls, success, handoff}
```

`dsh/phone/events` 在同一原生订阅中通过以下两种带类型的消息发送事件，`{type: "skillDraft", draft}`、`{type: "skillOutcome", name, display, state, change: promoted|suspended, from: {sessionId, taskId}}`。普通手机状态仍使用原来的无类型快照。Dart 提供独立的状态流和技能事件流。

`Draft.from`、`Skill.learnedFrom` 与 `skillOutcome.from` 都使用对话 ID 和手机任务编号。App 在后台收到草稿时复用普通通知渠道，点击通知携带 `sessionId` 打开对应对话。前台由界面接收事件。「不要」的五秒撤销由界面延迟调用 `skills.discard` 实现。

`skills.get` 和返回完整技能的方法另含 `body`（含 frontmatter）、`sections` 和 `history`（旧版毫秒时间戳）。列表中的技能是摘要。管理方法的业务错误使用 `{error, detail}`，包括 `changed`、`invalid`、`sensitive` 以及不可用或存储错误。`archived` 只列当前已删除且可从通道恢复的受管技能名。
