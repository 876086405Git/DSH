# 用高亮前后的字节差计算会话正文命中数

SQLite 派生索引写入正文前用 sanitizeFtsText 替换 NUL 及保留的 U+FDD0、U+FDD1。FTS5 highlight 对每段命中插入一个开标记和一个闭标记，重叠的词组共用一对。两个固定标记在同一数据库编码中的字节数相等。设原文字节数为 B、标记后为 H，每个开标记在该库的字节数为 b，段数为 k，则 H−B=2kb。旧式从 H 中减去删掉开标记后的长度，再除以 Node 绑定的开标记 UTF-8 字节数 3，得 kb/3。新式除以两个标记的 UTF-8 字节数之和 6，逐值相等。两个 JS Number 参数仍用 REAL 绑定，参数个数及排序的数值类型不变。

持久与活跃 FTS 分支分别从实际 SQLite 文本取 BLOB 字节数。不同数据库编码、表中已存在的版本 8 记录均沿用原来的计分。码点长度仍用于原有的次级排序。搜会话与在一个会话内搜事件共用此表达式；返回的摘要仍来自完整高亮文本。查询时减少反复生成高亮文本并替换起始标记的工作，写索引、数据库结构、分词、可见性、分页游标及片段截取维持原实现。

公共覆片登记于 session-cold-unused-fingerprint.diff 之后；在本题基底，OHOS 专属段没有别的覆片再改这个文件。直接使用会话查询服务的同名测试用 UTF-16LE 数据库验证命中排序与替换次数。SQLite 的高亮行为见 https://www.sqlite.org/fts5.html#the_highlight_function 。
